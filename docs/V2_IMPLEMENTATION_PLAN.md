## 2. 全程实施规则

### 2.1 状态定义

| 状态         | 含义                                        |
| ------------ | ------------------------------------------- |
| `待开始`     | 未实施，不得描述为可用                      |
| `进行中`     | 已在账本记录 START，允许有未完成代码        |
| `受阻`       | 依赖外部决策/材料，已记录阻塞和安全替代路径 |
| `待人工验收` | 自动验证通过，等待产品/真实环境验证         |
| `已完成`     | 代码、测试、文档和所需人工验收全部满足      |
| `已取消`     | 明确决定不实施，记录原因和替代方案          |

同一时间最多一个实施步骤为 `进行中`。并行的小任务仍归属于这个步骤，并在同一账本条目记录。

### 2.2 每一步的强制动作

1. **Before**：只读检查工作树，记录基准 commit、已有改动和当前测试状态。
2. **Scope**：列出本步允许修改和明确不修改的文件/模块。
3. **Implement**：保持改动可回滚，不混入无关重构。
4. **Test**：先最小相关测试，再执行本步规定的质量门。
5. **Document**：更新本文状态、变更账本、ADR、需求矩阵和相关专项文档。
6. **Handoff**：写清已完成、未完成、下一安全动作、已知风险和用户需提供的材料。

如果某一步只完成了一部分，不得将整个步骤标为完成。

### 2.3 变更记录最低字段

每条记录必须包含：

- 时间、会话/执行者、记录类型、步骤 ID、状态。
- 目标和实际结果。
- 修改文件完整列表；生成文件单独列出。
- 数据库 migration 和 IPC/Capability 变化。
- 测试命令、结果、未运行项及原因。
- 安全/隐私影响、兼容性和回滚方式。
- 新增/关闭的 ADR 或开放问题。
- 下一步，不得只写“继续开发”。

### 2.4 代码与安全纪律

- 不重写 v1-v8 migration；从新版本前向迁移。
- 不使用破坏性 Git 重置清理用户工作树。
- 新 AI 写入路径必须先有 Review Pipeline 测试。
- 新 Tauri command 同步更新注册、Capability、权限和注册测试。
- 前端不得访问密钥、绝对路径或数据库。
- 新日志/埋点先通过禁止字段测试。
- 新文件格式先建立 Zip Bomb、路径、大小、公式/宏和恶意内容边界。
- 大型模块拆分以行为保持测试为前提，不与新功能一次性混做。

## 8. 回滚与兼容策略

- 代码步骤保持小批量；功能通过 feature flag/路由隔离时，flag 不能绕过安全逻辑。

- 导入只建立授权引用或新成果，不原地修改来源文件。
- Review 应用失败同时回滚文件和数据库；恢复是新 Revision，不删除历史。
- 导出失败删除未完成临时文件，不删除 Result。
- Provider/检索/遥测关闭时，已有本地成果仍可打开和导出。
