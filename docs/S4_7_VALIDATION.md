# S4.7 Beta E2E 与发布验收验证记录

> 状态：实现与自动验证已完成，等待用户人工验收；通过前不得开始 S4.8。

## 验证目标

S4.7 不再逐个重做已经验收的功能，而是把分散能力组成用户可完成的 Beta 闭环：

- 四类 Beta 目标画像均有可执行入口和证据；
- 会议纪要、文档总结、周报、简历优化四个 P0 模板均可到达；
- 首次有效成果路径有 90 秒预算和实际测量；
- 文档、表格、清单、表单、小工具五类成果均有创建、编辑或保存/重开证据；
- 错误、取消、审阅、恢复和安全拒绝不会破坏已有成果；
- 会议纪要和文档总结两个高频场景分别记录完成、保存、导出及耗时数据。

“有效成果”在本阶段指包含用户可识别有效内容、已保存且可预览/继续处理的 Result；只有标题和空白结构的占位内容不计入。Web Mock 的导出只验证共享 Gateway/UI 流程，不会创建真实文件；真实文件仍由桌面人工验收确认。

## 本阶段发现并修正的产品缺口

首页“分析表格或数据”和“制作表单 / 清单 / 小工具”仍显示 S1.4 时期的未开放说明，与已验收的 S2.7/S3.x 能力不一致。现在：

- “分析表格或数据”直接打开新建成果，类型固定为“表格（CSV）”；
- “制作表单 / 清单 / 小工具”直接打开新建成果，类型只允许清单、表单和小工具；
- 顶部“新建成果”仍允许全部五类受控类型；
- 三个入口继续复用同一个 Result store、Gateway 和 Rust `create_text_result` 校验，不增加路径、权限、IPC 或文件写入旁路。

### 验证过程中的非业务不稳定

- 首次全量浏览器运行中，本机 Chromium 多次在 `page.goto` 前崩溃：最终为 13 项通过、3 项重试通过、1 项连续崩溃；最后一项导出场景隔离复跑 1/1 通过。加入仅用于测试的 `--disable-gpu` 后重新执行，17 项最终通过，其中 2 项仍因同类进程崩溃触发重试。没有业务断言失败，仍不能把本机 Chromium 记为“全部首轮稳定”。
- 首次 Rust 全量编译发生本机 rustc LLVM OOM；按既有单核/单 job 设置复跑。随后既有心跳/推理超时测试稳定复现测试 TCP 服务器协议错误；将测试服务器从手写 chunk framing 改为精确 Content-Length、完整写入、flush 与半关闭后，定向及全量均通过。生产 Provider 请求、SSE 解码与超时规则未变。
- 仓库级 `npm run format:check` 在当前 Windows 工作副本仍报告 111 个历史/CRLF 文件；S4.7 修改文件单独 Prettier 检查全部通过，未借本阶段批量改写无关历史文件。

自动测试使用虚构数据，不读取真实文件、凭据或 Provider，也不产生正式发布物。
