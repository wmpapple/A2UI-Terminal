# 安全响应说明

## 仓库密钥事件

仓库曾跟踪根目录 `.env`。即使当前工作区已删除该文件，历史提交仍可能包含旧内容，因此不能把“删除文件”等同于“密钥已安全清除”。

处理要求：

1. 将 `.env` 从当前版本移除并由 `.gitignore` 阻止再次提交。
2. 对其中曾使用的所有真实 API Key 执行轮换或吊销。
3. 在 CI 中加入 Secret 扫描。
4. 未经仓库负责人单独授权，不重写 Git 历史或强制推送。
5. M0-C 后，生产凭据改用 Windows Credential Manager；SQLite 只保存凭据引用。

## 报告安全问题

不要通过公开 Issue 提交 API Key、访问令牌、签名证书或包含用户数据的日志。应通过仓库负责人指定的私密渠道报告，并提供已脱敏的最小复现信息。

## 日志与诊断

日志不得记录：

- API Key、Authorization Header 或签名私钥；
- 用户未授权的文件正文；
- 完整敏感上下文；
- Credential Manager 返回的明文凭据。

诊断导出默认脱敏，并在导出前向用户展示内容清单。
