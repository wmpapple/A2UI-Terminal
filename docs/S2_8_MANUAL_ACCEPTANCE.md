# S2.8 Export Service 人工验收

> 范围：只验收 S2.8；通过前不得开始 S2.9。

> Web Mock 只演示流程，不会生成文件。以下文件打开检查必须在 Windows 桌面应用完成，不能用浏览器演示通过代替。

## 准备

1. 在项目根目录执行 `npm run desktop:dev`。
2. 从顶部“成果”进入，点击某个成果的“继续处理”，或点击“新建成果”，准备 Markdown、纯文本、CSV、清单和表单类型。左侧文件树直接打开的普通编辑器不是本次导出入口。
3. 确保每个成果已保存，并记住当前内容。

本机若再次遇到随机 Rust 编译崩溃，可在新的 PowerShell 会话中使用本次已验证的临时设置（不会修改全局环境或项目工具链）：

```powershell
(Get-Process -Id $PID).ProcessorAffinity = 1
$env:RUSTUP_TOOLCHAIN = 'stable'
$env:RUST_MIN_STACK = '33554432'
$env:CARGO_INCREMENTAL = '0'
$env:CARGO_BUILD_JOBS = '1'
npm run desktop:dev
```

本次使用已安装的 Rust stable 1.98.0。关闭该 PowerShell 后，以上临时设置结束。

## M01 文档格式与版本绑定

1. 打开 Markdown 类型的成果，修改并保存中文、英文和多行内容。
2. 点击成果顶部工具栏“另存副本”旁的“导出”（下载箭头图标），依次选择 Markdown、DOCX、PDF、RTF，并在系统保存对话框选择新文件名。
3. 分别用文本编辑器、Word 兼容阅读器和 PDF 阅读器打开输出。
4. PDF 加入至少 85 行中文，检查分页，并复制“第0行 会议纪要”和最后一行验证中文字符；纯文本 DOCX 加入 `#标签`、缩进和 `<>&` 检查内容保留。
5. Markdown 正文加入一级/二级标题、`> 引用`、有序/无序列表、`**加粗**`、行内代码和三反引号代码块。PDF 应显示标题层级、引用竖线、列表缩进、加粗和代码背景，不打印语法围栏；代码块内部的 `#` 等原文必须保留。用较长中英文段落检查按页宽换行，不能按固定 44 字符提前截断。

预期：四种文件均可打开，内容来自点击导出时的当前已保存版本；PDF 中文可见；UI 只显示文件名，不显示绝对路径。

## M02 表格格式与公式注入防护

1. 从顶部“成果”进入并点击“新建成果”，填写标题，在“成果类型”选择“表格（CSV）”；确认“内部格式”自动显示 `CSV`、文件名以 `.csv` 结尾，然后创建。
2. 在该 CSV 表格加入以 `=`、`+`、`-`、`@` 开头的文本单元格以及普通数值。
3. 分别导出 CSV 和 XLSX，并用对应工具打开。
4. 首行也加入公式型文本，并加入空单元格、引号、逗号、跨行字段和不等长行，确认首行/末行没有丢失。

预期：危险起始文本带前置单引号并作为文本显示，不执行为公式；普通数据保持可读。

## M03 清单与表单

1. 分别打开清单与表单成果，各自导出 JSON 和 PDF。
2. 清单 PDF 应显示完成标记与任务正文，表单 PDF 显示字段标签、类型和填写线；不能只打印内部 JSON。
3. 普通本地小工具可导出受控配置 JSON；A2UI Surface 协议快照不支持便携导出，入口禁用且 Rust 拒绝绕过。

预期：JSON 结构有效；PDF 可打开并包含当前结构化成果，不包含聊天、Prompt、上下文清单或调试信息。

## M04 取消、失败与重试

1. 点击导出后在系统保存对话框取消。
2. 再次导出，选择一个已有同名文件，在系统询问中先取消替换，检查原文件不变；重新操作并明确选择“替换”，应成功导出当前版本，而不是直接报错。请选择测试用副本，不要使用重要文件。
3. 用独占占用的文件或没有写入权限的位置制造失败，确认界面提示关闭阅读器/检查权限；点击“重试导出”，关闭占用程序或改用新文件名后成功。
4. 将 PDF 正文加入未覆盖字符（例如 Emoji），确认明确失败；换成原始格式、DOCX 或 RTF 重试，不得静默丢字。
5. 尝试将 PDF 保存为 `.xlsx`，应拒绝扩展名错配；检查目标目录不存在临时残留。

预期：取消明确显示“已取消”；只有在原生对话框明确确认后才允许替换已有文件。生成、写入或替换失败时旧目标保持完整，无临时残留；Result 内容、保存状态或历史不变，重试可以成功。正在编辑的源成果、应用管理成果目录、目录/符号链接/只读目标不得作为替换对象。

## M05 进度与并发版本变化

1. 导出一个内容较长的 PDF，观察准备、生成、写入、完成阶段。
2. 系统保存对话框打开期间，在外部编辑器修改源成果，再确认保存；应拒绝旧 revision，且没有输出文件。
3. 生成阶段取消或切换成果，随后检查目标不存在、原成果与历史仍可使用；快速重复点击只应出现一个导出任务。
4. 确认替换后、生成结束前，在外部修改测试目标文件；应报告冲突并保留外部新内容。选择新文件名后若被其他程序抢先创建，也不能静默覆盖。

预期：进度阶段可见；新旧内容不会混合，也不会留下 `.a2ui-export-*.tmp` 半成品。

取消边界：原生保存对话框需在对话框内按取消/ESC 关闭；生成器单次调用期间取消会等待当前生成返回，再阻止文件提交。原子提交开始后不再承诺取消成功。百分比表示阶段，不是逐页精确进度；短任务可能很快跳过中间画面。

## P0 明确限制

- PDF 支持基础 Markdown 标题、段落、引用、列表、粗体、行内代码、代码块与分页；表格按可读文本行降级，图片只显示替代文字，不读取图片文件或联网。原始 HTML 仅作为文本显示；不承诺完整 CSS/浏览器排版、Office/PDF 无损回写、宏、公式计算或嵌入对象保真。
- PDF 使用随包字体，未覆盖字符或同字形歧义会明确失败；不会联网下载字体或调用外部转换服务。
- CSV/XLSX 的公式型文本会增加前导单引号，XLSX 按字符串单元格导出；此为安全转换，不是数值/公式类型保真。
- 本阶段不测试正式签名/安装器发布；真实桌面保存与 Word/Excel/PDF 阅读器打开仍需按本单验收。
