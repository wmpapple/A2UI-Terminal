# S3.4 首批真实小工具人工验收

> 范围：只验收 S3.4；通过前不得开始 S3.5。

> 必须使用 Windows 桌面应用。Web Mock 不能生成真实 Provider Surface，也不能用浏览器下载代替系统保存对话框。

## 准备

1. 完全关闭旧桌面应用和旧 `desktop:dev` 进程，再在项目根目录重新执行 `npm run desktop:dev`。旧进程不会热加载 Rust/Catalog 变化。
2. 使用已配置且可用的 Provider，新建一个会话。无需选择或创建文件；本阶段的小工具不修改工作区文件。
3. 若本机再次出现随机 Rust 编译崩溃，可在新的 PowerShell 会话临时执行：

```powershell
(Get-Process -Id $PID).ProcessorAffinity = 1
$env:RUSTUP_TOOLCHAIN = 'stable'
$env:RUST_MIN_STACK = '33554432'
$env:CARGO_INCREMENTAL = '0'
$env:CARGO_BUILD_JOBS = '1'
npm run desktop:dev
```

## M01 真实检查表闭环

若旧版本提示“缺少用户要求的‘查看修改’动作”，请完全退出并重新启动桌面应用后，重新发送下面的原提示词。此问题属于自动保存意图误判，已修正；旧失败记录不会自动变为成功，不需要给小工具添加审阅按钮。

发送：

> 生成一个真实的中文交互检查表小工具，不要创建或修改文件。标题为“发布检查表”；项目包括“完成评审”（初始已完成）、“准备发布”和“通知客户”（初始未完成），并提供备注输入。界面必须显示实时“当前检查结果”，修改后自动保存为成果，可在成果页导出 JSON。

1. 点击该条 AI 回复中的“打开 Surface”。
2. 确认显示“发布检查表”、三个可勾选项目、备注输入和绿色“当前检查结果”，不是项目面板、聊天 JSON 或上一阶段的旧 Surface。
3. 勾选“准备发布”，取消“完成评审”，在备注中输入 `等待 QA & 客户确认`。

预期：结果摘要立即显示当前完成项目、`1/3` 和完整备注；没有“保存”按钮也不会丢失，因为每次受控输入都会自动保存。Inspector 显示安全校验通过，Catalog 共 20 个组件。

## M02 真实计划表闭环

新建一条消息并发送：

> 生成一个真实的中文交互项目计划表小工具，不要创建或修改文件。标题为“发布计划表”，任务为“准备 2.0 发布”，负责人 Ada，截止日期 2026-09-30，状态为“进行中”。必须允许修改这些字段，并实时显示“当前计划结果”；修改后自动保存为成果，可在成果页导出 JSON。

1. 打开本条消息对应的 Surface，确认不是 M01 检查表或历史项目面板。
2. 把任务改为“发布 2.0 正式版”，负责人改为“Grace”，日期改为 `2026-10-08`，状态改为“已完成”。

预期：四项输入均可修改；状态只能从“未开始/进行中/已完成/已暂停”选择；“当前计划结果”立即同步四个最新值。

## M03 成果、版本与重启恢复

1. 打开顶部“成果”，应看到标题为“发布检查表”和“发布计划表”的两个工具成果，而不是内部 Surface ID。
2. 打开检查表成果，确认只读成果显示“检查项目”和“备注”的可读值，不显示 `surfaceId`、`components`、`actions`、Prompt 或聊天正文。
3. 点击“历史版本”，确认 M01 的实际状态变化形成了多个版本；未改变值时不应不断增加相同版本。
4. 完全退出并重新启动桌面应用，再打开这两个成果。

预期：成果和最新可读值仍存在，当前 Revision 可用；普通旧 Surface 或 S3.3 审阅卡若出现在成果列表中，其无便携 Revision 的导出入口保持禁用，不能冒充真实工具。

## M04 JSON 真实导出

1. 在检查表成果点击“导出”，选择 JSON，并在系统保存对话框选择一个新文件名。
2. 用文本编辑器打开文件，确认包含 `settings`，其中有 `doneItems`、`notes` 及 M01 最后状态。
3. 对计划表重复导出，确认包含 `task`、`owner`、`dueDate`、`status` 及 M02 最后状态。
4. 用相同目标名再次导出并在系统对话框确认替换。

预期：两个 JSON 都能解析；内容绑定点击导出时的当前 Revision；替换按既有安全确认流程成功。文件不得包含绝对路径、API Key、聊天、Prompt、Context Manifest、原始 A2UI 消息、组件树、Action 或 Inspector 错误。

## M05 失败与隔离

1. 请求“在检查表里运行 JavaScript 或 Shell 自动发布”，不得出现可执行按钮或执行成功提示。
2. 在一个普通 S3.2 展示面板或 S3.3 审阅卡成果上检查导出入口；没有真实结果 Revision 时应禁用。
3. 返回 M01/M02，继续修改一个值，确认彼此状态不会串改，工作区文件内容也没有变化。

预期：Catalog 仍无 Script/HTML/iframe/命令组件，Action 仍只有三类；两个工具按 Surface/Result 隔离，S3.3 的 Review 安全边界不变。

## P0 明确限制

- 本阶段只交付检查表和单项项目计划表；计算器、对比器、多行可增删计划、公式和外部数据源尚未实现。
- 结果采用可读 JSON 投影，不承诺把协议组件树导出、把 JSON 无损回写为 Surface，或生成 PDF/Office 版工具报告。
- 状态变化由用户直接操作可信本地控件，不属于 AI 文件写入；工具不会创建或修改工作区文件。若后续 Action 提议文件修改，仍必须进入 S3.3 的 Review Pipeline。
