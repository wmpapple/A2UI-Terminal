# M8 产品验收

运行最新版 `logs/m8-formatting-fix-review/a2ui-terminal.exe`，或在项目目录运行 `npm run desktop:dev`。本阶段只验收结构化文档；不要将本文的代码围栏复制进正文。

正文格式补充验收：打开 Markdown 成果并进入“编辑”，在正文直接选中文字，点击正文上方“加粗”或“斜体”。跨列表行选择应保留列表结构；切换“阅读”可查看格式效果，自动保存后重开仍应保留。无需打开“结构化编辑”。

## 建议检查

1. 新建一个 Markdown 成果，把 `docs/V2.X/M8_SAMPLE.md` 的正文复制进去并保存。点击“结构化编辑”，应看到标题、段落、列表、表格和分页分隔。
2. 编辑一个普通段落，选中文字后点击“加粗”或“斜体”。点击“审阅本段修改”，先核对修改前后，再“接受并保存”。放弃时正文不应变化。
3. 修改一个表格单元格后离开输入框，确认提案再保存。标题级别、段落上移/下移、删除也应先展示提案。
4. 插入段落/列表、表格、PNG 图片与分页。PNG 限制为 1 MiB、宽高最多 4096 像素。查看普通预览；关闭面板、切换首页再回来，保存内容应还在。
5. 在成果“导出”中选 Word，检查标题、粗斜体、表格、PNG 与分页。列表为可见编号，复杂 Word 样式不是本期验收目标。PDF 的图片为说明、表格为文本行，分页应生效。
6. 新建另一个 Markdown 成果，在结构化面板点击“导入 Word / Markdown”，选第 5 步的 Word 或样例 Markdown。接受前目标正文不变，接受后出现副本内容；原文件不应被修改。合并/嵌套表格应明确提示不支持。
7. 用“历史版本”恢复修改前正文，再重开结构化编辑检查。工作区授权的 Markdown 文件也检查一次段落编辑；PDF/Word 原始资料继续只读。

如果正文有未保存草稿，先保存；结构化编辑只针对已保存版本。源码中复杂链接/代码段落会使用源码编辑，避免无意丢失语法。新增段落与表格行列可用 Markdown 源码调整。

全部符合预期后，回复“M8 验收通过，开始下一阶段”。在此之前不进入 M9。
