## 联调修复

- 本地无 Key 模型不再依赖系统凭据服务可用；已保存 Key 仍按配置使用，云端凭据失败仍拒绝发送。Provider 列表不因某个云端凭据读取不可用而阻断本地配置。
- 空 Key 不发送空 Bearer 头。本机回环 Endpoint 直连，不经过系统/配置代理，也不跟随重定向；IPv6 回环地址通过与本地探测一致的校验。使用固定本机服务验证无凭据头、代理不介入及 307 不跳转。
- 自动更新读取应用版本补齐 `core:app:allow-version` 最小只读权限，版本 IPC 失败也进入可见错误状态，不产生未处理 Promise 拒绝。真实 WebView 长于启动烟测的流程捕获了该问题。
- Inline 新增与完整生成一致的可信凭据注入测试入口，仅供 Rust 适配和整链测试使用；桌面 IPC 仍只提供原有入口，测试不读取真实 Key。

## 可复现入口

- `npm run test:beta:integration`：临时数据库、100 份虚构资料、真实本机 SSE、写作整链和导出回读。
- `npm run tauri build -- --debug --no-bundle`，随后 `npm run test:beta:desktop`：真实 WebView2、公开 IPC、独立临时目录、凭据禁用；脚本只在本次子进程开启本机 CDP，退出后清理本次临时目录。
- `npm run audit:product-beta`：核对本轮 Rust/前端/浏览器日志、真实桌面报告与性能样本；与旧 `audit:beta-evidence` 分开。

桌面脚本通过已有公开操作验证写作与保存，不绕过导入权限。真实文件导入/引用整链由 Rust 临时资料用例覆盖，两类证据不拼写成“桌面已通过原生文件选择器导入”的测试记录。

## 性能口径与边界

- 资料基准为 100 份、每份约 650 字的虚构 Markdown，列表首屏 40 项，检索 1 次冷查询 + 20 次热查询；采用当前内存词法检索。固定任务包含预算、中文和数字，不代表大 PDF 或千份长文规模。
- 桌面测量区分应用内部 `homeInteractive` 与“启动到首页（包含本次测试配置及一次重载）”耗时；成果打开重复采样 5 次，反馈是本地交互响应，不是 AI 完整生成时长。原始值与计算口径见 `logs/b0-desktop/report.json` 和 `logs/b0-evidence.json`。
- 本轮没有持久索引、Embedding 或千份资料承诺；这些仍属于 M5。没有签名安装/升级或外部真实模型评测证据，不使用本次通过数冒充这些发布门。
