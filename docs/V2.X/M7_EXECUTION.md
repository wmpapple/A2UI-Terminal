## 范围与行为

人工验收漏检修复另见 `M7_FORBIDDEN_WORD_FIX.md`；原 `M7_DELIVERY_SNAPSHOT.json` 保留为首次交付证据，不代表修复版二进制。

在成果和已授权工作区的 Markdown/纯文本编辑器提供“文档审稿”。打开面板即检查已保存版本；本地规则不请求 AI、不读取凭据、不修改正文。支持术语和禁用词、句段长度阈值、标题跳级、完全重复段落、数字缺少可核验引用以及失效引用。代码块与行内代码不参与术语和引用检查。数字提示是来源核对线索，不将缺少引用等同于事实错误；有效引用也不等同于其支持文中全部论断。

提示可查看原文与行号、忽略、恢复，或选择“让 AI 修改”。最后一种操作复用既有 Inline Edit 与 Review：规划选区的发送清单、主动确认、生成修改提案，再由用户接受后写入。整个文档审稿接口不接受或执行模型提供的路径、写入操作和目标。正文有未保存修改时，提示停用。

可选“AI 深度审稿”检查疑似逻辑冲突、观点重复、风格和结论。继续使用用户配置的 BYOK/本机服务，不增加内置服务。规划本身不调用模型；清单包含已保存正文、当前写作偏好及可核验引用片段。正文不能完整进入上下文预算时拒绝这次整篇审稿，提示检查较短文档。关闭/停止会取消审稿，不自动重试。

## 实现与边界

- 迁移 `0027_critic.sql`，保留每个目标的最新本地报告与 AI 报告及忽略状态；重开恢复。成果/工作区删除级联清理，工作区文件撤销授权清理相关审稿快照，“清除本地数据”包含本表。
- 报告签名包含文档目标、正文 hash、成果 revision 或工作区保存历史、写作偏好 hash、实时引用状态、规则版本和阈值。正文改版、原文恢复为相同内容、偏好变化或引用失效后，旧提示不能再触发修改。
- UI 通过现有 Gateway/DTO 调用 Rust application；服务器从已授权目标重新读取正文。UTF-16 位置由可信代码从原文计算，涵盖中文、emoji、CRLF。
- 补齐目录文件的稳定 `documentId`，与独立文件的 `sourceId` 分开。解析时重新枚举当前目录授权范围并走原有路径检查；打开文件不另建授权记录、不创建成果、不改变自动保存或 AI 上下文的原有来源路由。目录移除、文件移出目录、跨工作区标识均不能继续定位。已有绑定成果的目录文件沿用同一引用及修订信息。
- AI 只可返回严格 JSON，最多 20 项。原文必须真实存在且能唯一定位；对照原文也必须存在。未知字段、可执行字段、不存在/多义的定位以及超长输出均拒绝，不修改正文。
- 本地单次最多 100000 字、100 项提示；AI 请求另受当前模型上下文预算限制。规则版本 `critic-v1`，AI 报告记录该版本及 Provider/模型标识。每次发送重新校验确认清单、服务配置、版本与来源；响应完成再次校验，取消/过期结果不持久化。
- 查看原文使用显示准确片段与行号的窗口；首版不增加新的编辑器定位协议。审稿目前不直接支持 PDF/DOCX 原件、表格或结构化成果。提取内容仍沿用前期的引用能力。

## 质量与验证方法

工程验证与模型审稿准确率分别记录。固定规则测试覆盖重复、标题、长度、术语边界、代码排除、引用状态和 Unicode 定位；集成测试覆盖版本/偏好/授权变化、忽略状态重启恢复、未保存草稿、数量与长度上限、清空数据、网络期间改稿与取消。真实 HTTP SSE 固定响应走生产的清单、Provider、解析和 Inline/Review 写入链路，证明操作边界，不证明真实模型的发现率或误报率。

本阶段不认证任何 BYOK 模型的逻辑/事实审稿准确率，也不复用 M6 失败的小模型评测作为 M7 合格证据。AI 输出始终标为待人工核对的建议；严格格式或定位失败时，保留本地规则结果供继续使用。后续评估模型时，应使用固定的有矛盾/无矛盾、有意重复、语气差异和结论缺失样例，同时评估误报、漏报与定位成功率，不只评估返回 JSON。

自动验证记录及最终程序 hash 写入 `M7_DELIVERY_SNAPSHOT.json`。桌面脚本使用独立临时数据目录、禁用真实凭据，仅请求回环固定响应，不读取用户资料或调用付费服务。产品验收步骤见 [M7_MANUAL_ACCEPTANCE.md](M7_MANUAL_ACCEPTANCE.md)。
