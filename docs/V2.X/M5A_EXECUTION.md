## 实施范围

- 首页“搜索本地内容”使用本机 SQLite FTS5 持久索引，包含个人资料、可读取成果、当前工作区授权来源和资料包名称。IPC 接口保持兼容形状，`indexMode` 更新为 `persistent_lexical`，同步更新 Rust / TypeScript / Mock / 契约 fixture。
- 当前 bundled SQLite 的 FTS5 通过实际建表、查询和编译选项测试验证。沿用原有中英文分词，中文连续字使用 bigram；将词编码成单个 ASCII token 后交给 FTS5，避免默认 unicode61 把连续中文视作一个词，也避免查询字符串成为 FTS 操作符。
- 使用 FTS5 BM25 排名，同一来源只显示最相关片段；同分按来源和片段顺序稳定排序。固定中英文字词、数字、下划线和重音字符用例与既有 bigram 排名对照。没有将有限词法样例解释为语义检索质量提升。
- 新增迁移 0024，历史迁移保持不变。来源指纹、索引版本、片段起止字符、正文及倒排数据持久化。未变化的个人资料只读取元信息，不重新反序列化正文或分块；成果和外部工作区文件每次重新读取验证，防止外部修改和失效授权返回旧内容。
- 新增/变更来源按批增量写入，每批最多 16 个来源；分词在事务外，提交后可在中断重启时复用已完成批次。数据库迁移不解析资料，不在启动时全库重建。
- 删除资料、成果、资料包、工作区，以及撤销文件授权，会在同一数据库事务内清理对应派生索引。来源变更计数阻止并发删除/改动后把旧快照重新写入或返回。全部本地数据清理覆盖索引和倒排数据。
- “修复搜索”重置派生数据，下次搜索自动重建。先修复倒排结构再清空，覆盖倒排条目缺失的恢复路径；不会改变成果正文或删除真实来源文件。搜索和修复通过后台线程执行，界面沿用加载和错误反馈。

## 边界

本次是本地内容搜索底座。资料库列表仍按已有分页/筛选接口工作，AI 发送清单仍只处理明确选择并确认的资料，使用原有预算与检索策略；本次不会自动把整个资料库放入模型上下文，也不会把搜索片段认作已验证引用。M4 请求级引用映射保持独立。

M5-B 的 Embedding、混合排名、模型选择和额外资料发送授权均未开始。没有增加模型服务、联网依赖或第三方包；BYOK + 本地模型策略保持。单字中文和同义词不作新能力承诺。本次规模基准是合成文本资料，不能代替大量外部工作区文件、超长 PDF 或多工作区重复索引规模的测量。
