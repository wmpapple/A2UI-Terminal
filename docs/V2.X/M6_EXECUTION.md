## 本阶段范围

从首页“长文项目”进入，保存目标、读者、资料选择、关键事实和术语。大纲可手动编辑、增删和排序，也可先让 AI 提出大纲，用户确认后才能进入正文生成。首版每个项目 1–12 章，每章建议 100–5000 字；建议长度指导模型，不是精确字数承诺。

每次只生成一章，前章接受后才可继续。用户审阅/修改正文，并确认供后章使用的事实摘要；摘要是连续性上下文，不冒充已核实证据。每章独立保存请求快照、模型、Prompt 版本、写作偏好和来源清单。后章发送大纲、事实及前章摘要，避免自动重复发送完整前文。重写、扩写和精简可通过本章额外要求完成。

项目、章节、生成记录、部分输出和手工章节草稿保存在 SQLite。离开页面不会自动开始下一章；重启将未完成请求标为中断，保留已有输出，不自动重试收费请求。每个项目仅允许一个运行中的请求；项目修订号、一次性计划和持久唯一约束防止双击、重复接受和重复合成。改变前章后，后章保留正文并标为需要复核。

所有章节被接受后，用户查看全文并主动合成为一个 Markdown Result，复用既有审阅/成果写入事务与幂等恢复。各章引用重新编号后绑定合成成果；未知引用保留待核对标记，不与其他章的合法编号混淆。来源删除后继续沿用 M4 的不可用/撤销/过期状态。

## 实施决定

- 新增迁移 0026。项目配置、大纲和最多 12 章的接受状态作为一个有修订号的聚合存储；独立运行记录及草稿单独持久化。没有照抄参考文档中已被前期迁移占用的编号。
- 继续使用已有 Context Manifest、预算/资料授权检查、Prompt Composer、BYOK/本地 Provider 和引用模块。共享 Manifest 改为独立 ID + 10 分钟 TTL + 容量上限，规划新请求不再清空其他请求。
- 发往模型的数据仍需明确确认。M5 语义搜索不自动发送全库给长文任务；资料必须在项目中选择，实际片段以每次清单为准。
- 正式的主动事实/逻辑/风格审稿属于 M7；本阶段提供逐章人工审阅、引用来源检查和一致性摘要。来源存在不等于事实正确。
- 未替换编辑器、未增加默认云服务、未启动后续阶段。输出质量按固定长文用例独立记录，不用 M5 的检索成绩推断写作质量。

使用本机 CPU 上的 `onnx-community/Qwen3-1.7B-ONNX`，revision `cc6a06a21d614e9b8e92a6adfab1074d4e7d2438`、q4、贪心解码、关闭 thinking、每章最多 1800 个新 token。可选运行时 `@huggingface/transformers@3.8.1` 复用忽略目录中的评测依赖，不加入产品依赖或安装包。模型由公开镜像下载固定 revision，推理禁止远程加载，只向本机回环服务发送固定虚构资料，未读取用户凭据。

每章经过生产环境相同的规划、显式确认、Provider HTTP、Prompt Composer、来源映射和合成流程。测试脚本代替评测人员接受生成文本、填写固定的已知事实摘要，以保持两份评测输入一致；产品仍由用户逐章审阅、填写摘要并接受。每份案例运行一次，无法据此估计稳定成功率。生成建议长度不作硬性字数承诺。
