# M7 产品验收

启动 `logs/m7-critic-fix-review/a2ui-terminal.exe`，也可使用 `npm run desktop:dev`。本阶段只需检查产品功能，工程测试由开发侧完成。

1. 新建或打开 Markdown/纯文本成果，保存下面的示例，然后点“文档审稿”。应出现标题跳级、数字来源待核对的提示；在“设置 → 写作方式”启用禁用词“赋能”后，还应出现禁用词提示。

   只复制示例中的正文，勿复制首尾三反引号及 `markdown` 标记；否则整篇会被当作代码块跳过检查。

   ```markdown
   # 项目说明

   ### 预算现状

   预算 420 元，尚未批准。

   我们希望赋能团队。
   ```

2. 点“查看原文”，核对片段和行号。忽略一项，关闭面板后重开；勾选“显示已忽略提示”可以恢复。退出程序再进入同一成果，已忽略状态应保留。
3. 修改并保存正文后再检查，旧版本的提示不应继续用于修改。编辑尚未保存时，面板应提示先保存。也可以在系统目录选择器授权的工作区文本文件中检查同样功能。
4. 使用已配置好的 BYOK 或本机聊天模型，点“AI 深度审稿”。核对发送清单，确认后等待结果。过程中正文不应变化，可以停止生成。模型返回无效格式或无法定位的原文时，应显示错误且保留正文。
5. 对某项提示点“让 AI 修改”，确认发送范围后查看修改前后。关闭提案不应改变正文；“接受并写入”才保存修改，并可在已有历史版本中检查/撤回。

本地检查无需模型。AI 建议可能误报或漏报，来源存在也不代表每个事实已核实；本阶段没有认证通用审稿准确率。无需为了这次验收更换原有模型或重新配置向量服务，深度审稿使用聊天模型。

禁用词需在写作偏好中输入后按回车，启用该套偏好并点击“保存偏好”。保存含该词的正文后打开“文档审稿”，在“本地规则”中查看提示；这不是输入时自动弹出的提醒。标题、列表、引用和普通段落均参与检查，代码块和行内代码除外。已忽略的提示需勾选“显示已忽略提示”查看。

完成后反馈“M7 验收通过”或描述发现的问题。未获得人工验收通过，不进入下一阶段。
