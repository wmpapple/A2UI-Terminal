# M9：Contextual A2UI Tools（场景化工具）

本补充由用户授权，属于 M9，不表示 M10 已开始。产品方向是“资料 → 成果 → 行动”，不把 A2UI 限定为文档插件。

## 工具分类

2026-09-30 更新：所有场景工具都可独立使用，不要求绑定文件或其他对象。「文档审核」「发布检查」只是用途分类，不是创建前提。关联 Document、Result、Task、Workspace 均为可选操作，已有工具也可以解除关联，保留填写内容。

| 类别         | 创建约束                      | 本阶段入口与示例                                                         |
| ------------ | ----------------------------- | ------------------------------------------------------------------------ |
| 文档审核用途 | 可独立使用，可选关联          | 发布检查表、文档审核表；可关联文档成果和已授权 Markdown/纯文本工作区文件 |
| 成果关联型   | 关联已有 Result，无需寻找文件 | 任务清单、采访提纲、信息收集表可关联已有文档、表格或工具等成果           |
| 独立型       | 不要求关联                    | 采访、收集、任务清单直接填写，自身状态自动保存，成果由用户手动保存       |

Task、Workspace 也是可用的关联目标。任务核对覆盖任务元数据；工作区核对只覆盖名称和身份，不表示工作区中全部文件已经检查。旅行计划等专用业务 Result 类型尚未新增，不在界面中冒充已实现。

## 模型与现有代码的对应

`ToolInstance` 复用底层存储记录、A2UI Surface 与版本记录，但不自动拥有产品层的成果身份：

- 内部记录提供 id、标题、创建时间；带 `scene_tool_instances` 元数据的记录不进入成果列表、首页成果、搜索成果或关联目标选择器。
- Surface 提供安全组件树与填写 state。
- `scene_tool_instances` 保存 templateId、bindingPolicy 及可选的 publishedResultId。
- `scene_tool_bindings` 保存 binding、目标名称、关联时 revision/hash、人工核对 revision/hash/time、并发版本。
- `scene_template_policies` 保留个人模板的类别约束，不保留绑定目标、上下文、核对标记或个人填写值。

## 自动保存与手动成果

场景工具状态自动保存在「工作台 → 我的工具」。创建、填写、导出、存为模板都不会发布成果。点击「保存为成果」才创建独立的只读快照；后续填写不改动该成果，点击「更新成果」才更新同一个成果并记录修订。

界面只用“正在保存／已自动保存／自动保存失败”表达工具状态，不提供额外保存按钮。成果关系另行表达：未发布时显示“保存为成果”，发布且内容一致时显示“已同步”，工具内容或名称变化后显示“更新成果”。发布记录包含成果标题和可读修订序号；更新始终写入同一个成果并增加修订。

实例级操作属于工具工作台。重命名、更换关联、重置、删除和保存为个人模板位于更多菜单；导出与成果按钮保留为主操作。每个工具实例都可删除，删除实例会清理其 Surface、关联和运行状态，但不会连带删除已经由用户手动保存的成果。

## 页面职责与创建流程

模板页仅负责从定义创建工具，提供推荐模板、内置场景工具模板与我的模板，移除说明蓝框、实例列表和跳首页入口。内置卡片统一为“使用模板／自定义”；“自定义”只影响本次 ToolInstance，不自动生成个人模板。所有模板都用轻量标签如实说明用途与“可独立／可关联”，不把文档用途重新解释成强制绑定。

个人模板显示用户身份、更新时间和来源模板；空状态从“前往我的工具”解释保存路径。复用个人模板仍清空填写、绑定、核对与成果关系。旧工作区交互模板继续兼容并标为“其他交互模板”；文档模板是后续能力，不展示尚未实现的入口。当前只有五个内置模板，不增加搜索、筛选、收藏或分类侧栏。

工作台提供「文件 / 我的工具」切换，分别保留当前对象；实例列表显示关联对象的已保存名称，不为显示列表额外读取目标正文。工具保存、导出使用自己的数据读取，不覆盖文件侧 Result 的编辑草稿。

实例列表用第二行区分同名工具：有关联时显示目标名称，独立使用时显示创建时间，已经发布时增加“已有成果”标识。每行提供删除入口。工具标题可重命名，重命名后若已有成果会进入“尚未更新”状态，由用户决定是否更新成果。

五个预设都可通过“使用模板”直接创建并打开，也可通过“自定义”调整本次工具的名称、字段与可选关联。发布检查与文档审核同样可独立使用，或选择当前文档、工作区文件、成果、任务、工作区。创建成功后直接打开 ToolInstance；关联只是上下文选择，不新增授权。

保存为模板只保留结构与默认配置，清空填写值；新实例不继承旧绑定、核对状态、运行事件和成果发布关系。保存为成果走独立快照路径，两者互不替代。

快照与实时工具使用不同身份和存储引用，避免重新收集 Surface 时覆盖成果。发布事务同时比较工具状态和已发布修订，旧页面不能覆盖较新的填写或成果。成果快照展示保存的填写内容；实时关联核对状态继续在原工具中查看。

Schema 30 给工具实例添加发布关系。旧版自动放进成果列表的场景工具迁入「我的工具」，保留填写、关联与历史；不删除其数据，也不替用户执行首次成果发布。未发布工具仍可从关联对象进入。

Schema 31 统一将已有工具与个人模板的关联策略改为可选，不删除已有绑定、核对记录、填写值和成果发布关系。新建的所有内置工具同样采用可选关联。

Binding 为带类型的联合：

```json
{"type":"none"}
{"type":"document","target":{"kind":"result","resultId":"…"}}
{"type":"document","target":{"kind":"workspace_file","workspaceId":"…","sourceId":"…"}}
{"type":"result","targetId":"…"}
{"type":"task","targetId":"…"}
{"type":"workspace","targetId":"…"}
```

Document 复用 F0 的 DocumentTarget，不把文件路径当作授权凭证。工作区文件仍需通过当前授权解析，关联不会偷偷创建一个文档 Result。文档成果记录 revisionId；工作区文件使用已有历史版本（存在时）和内容 Hash，没有历史版本时以内容指纹标识。

## Binding 与 Context

Binding 表示工具属于谁；Context 是当前可展示的内容，两者独立：

- 文档：最多 2000 字预览、现有引用状态、已有 M7 本地／AI 审稿报告。
- 其他 Result：已有成果的内容预览，不要求后端文件。
- Task：任务元数据；不会启动任务或模型。
- Workspace：工作区身份，不枚举全部文件正文或扩大授权。
- None：只使用当前工具的填写内容。

所有内容由已有读取与授权逻辑解析。绑定不授予新的个人资料、工作区资料或模型发送权限。引用摘录沿用原有引用授权，来源核验不等于事实为真。M7 报告按正文、修订、偏好、引用等原签名判断是否有效，过期发现不冒充当前问题；打开工具不会自动运行审稿或调用 AI。

后续若增加额外知识选择，必须单独定义 Context 选择、来源授权与发送清单。不能从 binding 推导“全部资料已获发送许可”。

## 核对与失效

状态包括独立、待核对、当前已核对、目标已变化、有未保存修改、目标不可用。关联与人工核对是不同操作：

1. 创建或更换关联时记录目标身份和当时版本，不自动勾选、不判定可发布。
2. 用户确认前同时检查目标 Hash、revision、填写状态 Hash 和关联并发版本。
3. 正文恢复为相同文字但产生新修订，也需要重新核对。
4. 修改工具填写内容清除人工核对标记，保留填写记录。
5. 删除或撤销目标授权后，显示不可用，不继续展示缓存正文；工具填写仍可使用，也可解除关联。
6. 更换或解除关联清除核对标记、保留填写值。所有工具均可解除关联或选择其他类型对象。
7. 页面打开、窗口重新获得焦点和可见页面定时刷新时重新核验；不是操作系统文件监听。
8. JSON/PDF 导出附带导出时读取的关联状态和核对信息，不宣称是不可撤销的发布证书。

外部文件写入无法纳入 SQLite 事务，确认后会再次读取目标；变更会显示失效。第三方在两次观察之间改动又恢复、且没有应用内历史记录的情况，只能按最终内容指纹判断，不能声称追踪到所有外部编辑事件。

## 权限与迁移

Schema 28 → 29 增加三张本机关联元数据表，填写成果仍使用原存储。工具删除级联删除实例／绑定；目标删除保留关联身份用于提示不可用。clear-all 同步清理新表。

升级前创建的旧工具保持可用且不推断绑定。Schema 31 起，新旧工具与个人模板全部支持独立使用，已有对象关联继续保留，由用户决定是否解除。

## 与后续阶段的边界

M7 的修复仍进入现有文档审稿／Review／Inline 流程，不给工具加入绕过审阅的写入权限。当前可从工具打开关联成果继续处理；工作区文件通过原文件入口处理。

后续可以沿用：

```text
Source / Result → Contextual Tool → A2UI Surface
                                   ↓
                            受控 Action → Action Orchestrator
```

M10 的外部来源、身份与分享沿用这里的目标模型，同时独立处理外部授权与上下文发送。航班、酒店、地图、日历等 ExecutableAction 属于后续设计，不因本阶段支持绑定而获得执行权限。进入下一阶段仍需用户人工验收并明确授权。
