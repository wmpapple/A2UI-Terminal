# M4 产品功能验收

你只需验收功能、体验和输出结果；代码、权限、数据迁移、自动测试及构建由代理负责。完成本轮后须由你确认，才进入下一阶段。

验证程序：`D:\A2UI\A2UI-Terminal\logs\m4-citations-review\a2ui-terminal.exe`。关闭旧版窗口后打开；也可在项目目录执行 `npm run desktop:dev`。自动测试使用临时数据，未替你验收真实模型输出。工程结果见 [M4_DELIVERY_SNAPSHOT.json](M4_DELIVERY_SNAPSHOT.json)。

1. **旧资料升级**：打开资料库。有旧解析资料时应显示定位完善进度；可以暂停、继续，失败项可以重试。原文件不改变。
2. **带来源生成**：从成果打开 Markdown/TXT 文档，选择一份资料，要求“根据资料总结预算、负责人和日期，并标明引用”。发送清单中可展开“本次可引用片段”。生成并接受后，正文中的 `[S1]` 等编号应在“引用来源”中有对应入口。
3. **原文定位**：点击入口应看到所发原文与位置。分别验证 PDF 页、DOCX 段落、MD/TXT 行、CSV/XLSX 工作表和行列。扫描 PDF 不应假装有可提取正文；降级资料不应编造精确位置。
4. **未知引用**：手工输入 `[S999]` 并保存，应显示“未知引用”，不能显示“来源已核验”。
5. **修改与恢复**：对带引用的正文手工或 Inline 改写并保存，应提示引用待重新核验。恢复原历史版本后，仅当来源仍有效时才重新显示来源已核验。另存副本后也可读取原文。
6. **重启与删除**：重启后重开成果仍可查来源；删除生成时的聊天不应破坏独立成果。删除资料副本后，成果正文仍保留，但来源预览不可用。移除工作区来源后，应显示授权已撤销。
7. **聊天与导出**：普通聊天的带编号回答同样可预览来源；导出文档应附来源列表，包括标题、定位和当前状态。

注意：“来源已核验”不等于“事实已核实”。验收输出时仍要检查引用的原文是否真正支持对应断言。
