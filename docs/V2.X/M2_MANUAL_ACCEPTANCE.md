# M2 产品功能验收

本轮只验收 M2 的产品功能和使用体验。代码、数据库迁移、权限、自动测试、构建和浏览器进程异常已由代理检查；你无需执行工程命令。

验收程序：[M2 写作偏好验证版](../../logs/m2-writing-profile-review/a2ui-terminal.exe)。这是免安装 debug 版本，可直接启动；主窗口已经实际启动并检查，不存在上阶段曾出现的白屏。

## 1. 全局写作偏好

1. 打开“设置 → 写作方式”，启用“全局偏好”。
2. 在写作规则中填写一条容易识别的要求，例如“先给结论，每段不超过三句”。
3. 添加术语，例如“AI → AI 助手”；添加禁用词，例如“赋能”。保存前，下方应立即变成“保存后规则预览”，显示“未保存”并实时更新 token 和规则，不应仍显示 `0 tokens`。
4. 保存后检查下方“当前有效规则预览”：应显示全局偏好、`m2.1`、token 数和刚填写的规则。界面不展示内部修订号，以免被误解为可浏览的历史版本。

## 2. 工作区覆盖

1. 在工作台打开一个真实工作区，再进入“设置 → 写作方式”。
2. 切换到“当前工作区”，启用并填写一条只适用于该工作区的规则。
3. 可添加与全局同名、写法不同的术语。保存后，有效预览应同时显示 Global 和 Workspace 两层，工作区术语采用当前工作区写法。
4. 切换到另一个工作区或独立文件环境，不应错误沿用前一个工作区覆盖；全局偏好仍可用。

## 3. 范文引用边界

1. 在 Profile 中选择一项个人资料作为“范文引用”并保存。
2. 进入工作台发送请求并生成发送清单。
3. 清单应提示范文仍需本次上下文授权；如果没有在上下文中选择该资料，它不得出现在“将发送”的资料中。
4. 在上下文中明确选择并确认后，它才可作为本次资料发送。

## 4. 发送清单与生成效果

1. 在工作台聊天或 Markdown/TXT 成果助手中输入写作要求并打开发送清单。
2. 清单应显示“写作偏好快照”、生效层、`m2.1`、快照短指纹和 token 数；展开“查看本次有效规则”能看到具体规则。
3. 确认后生成内容，观察术语和风格是否按你的规则产生可解释差异。模型输出仍需人工审阅；本阶段不承诺每个模型都完全遵守风格。
4. 保持资料范围不变，修改并保存 Profile 后再次发送。程序必须重新展示清单，不能沿用旧偏好确认偷偷发送。
5. 在当前要求中明确给出与长期风格不同的本次要求，例如“本次使用正式长句”，检查当前要求能否覆盖长期写作偏好；安全和审阅流程仍不能被覆盖。

## 5. 持久化与重置

1. 关闭并重启程序，之前保存的 Global / Workspace Profile 应仍存在。
2. 重置 Workspace Profile 后，全局规则应保留；重置 Global 后应显示当前未启用全局写作偏好。
3. 重置后再次生成发送清单，应看到新的或禁用状态的 Profile 快照，并重新确认。

反馈时只需说明操作步骤、实际表现和期望表现。确认 M2 通过并明确允许后，才会开始 M3。
