# M3 Inline AI 与风险自适应审阅实施记录

日期：2026-09-24。M2 已由用户完成人工验收并明确授权 M3。本轮只实施 M3；M4 未启动。

## 已交付范围

- Markdown/TXT 成果编辑器和已授权文本文件编辑器共用同一套选区行内修改：润色、缩短、扩写、专业、自然、语法、翻译和自定义改写。
- 生成后在原编辑流中展示原文与 AI 建议，可接受、重新生成或关闭。接受前不写文件；重新生成和关闭不产生 Revision。
- 接受复用 Review、Patch、Revision 和 Undo。成果与工作区文件均产生一个可撤销版本；重复接受由后端保持幂等。
- 模型只返回替换文字。文件目标、基础版本、UTF-16 起止位置、选区哈希和低风险等级均由受信任程序锁定，模型不能指定路径、范围、风险或写入动作。
- 只发送当前连续选区和 M2 写作偏好，不隐式发送当前文件其余内容、最近对话、资料库或资料包。云端敏感内容仍需显式确认；本地模型不增加该确认。
- 未保存草稿、只读文件、预览 DOM、选区变化、文件变化、目标切换、模型切换和迟到响应均不能应用旧建议。接受时再次校验选区，落盘时再次校验基础哈希。
- 中高风险修改继续使用完整 Review；Inline 入口仅允许单目标、单连续选区的低风险文本替换。

## 工程边界

- Rust 新增 `application/inline_edit.rs`，复用 Context Manifest、Provider、Prompt Composer 和流式取消注册表。
- 新增 `plan_inline_edit`、`start_inline_edit` 两个 IPC 命令及最小 Tauri capability；内部临时会话在清单规划后立即清理，不出现在用户聊天历史中。
- 工作区已有非空文件使用受信任全量候选落盘函数。该函数只接收程序解析出的授权路径和基础哈希，并保留写前冲突检查、原子写入、Patch 快照和 Undo。
- 新增 `contracts/v2/inline-edit.json`，明确模型输出字段与受信任字段的边界。

## 自动验证覆盖

- UTF-16 与重复文本：包含 emoji 的第二处相同文本只修改指定范围。
- 工作区文件：接受、重复接受幂等、Revision/Undo、关闭零写入、生成后用户修改导致冲突。
- 成果：接受只新增一个 Revision，Undo 恢复原文。
- 前端：八种低风险动作、中文输入法组合态、生成后原地建议、接受前零写入、接受后调用应用链路。
- 命令注册、权限、类型、格式、Lint、前端全量测试、Rust 全量测试、Clippy、生产构建与桌面构建纳入阶段门。
