# M6 产品验收

本阶段仅交付长文项目。请确认产品体验，工程测试、构建和质量评测由代理完成。未开始 M7；本阶段通过后也需你明确授权才能进入下一阶段。

验证程序（滚动修复版）：`logs/m6-scroll-fix-review/a2ui-terminal.exe`。也可以在仓库运行 `npm run desktop:dev`。入口：**首页 → 长文项目**；首次没有工作区时点击“创建写作空间”。使用设置中已有的 BYOK 或本机聊天模型，不需要向量模型才能写作。

## 建议验收流程

1. 新建项目，填写标题、目标和读者，选择资料库资料或当前工作区已授权文件。可填写关键事实和术语，例如“预算 420 元，尚未批准，截止日 2026 年 10 月 15 日”。保存项目。
2. 点击“AI 生成大纲”，核对发送清单再确认；也可以手动添加章节。修改标题、目标、顺序和建议长度，然后点击“确认大纲，进入章节”。确认前不应直接生成正文。
3. 生成第一章，查看正文和引用来源；修改正文，填写供后章使用的事实摘要。回首页再进入长文项目，草稿应保留。退出程序重新打开后，从项目列表选择原项目并进入“章节与成果”，仍可恢复草稿。
4. 接受第一章，再生成第二章。后章应考虑前章摘要；模型文字需要人工核对。可停止生成后查看保留内容，再主动重试；不应自动进入下一章。
5. 返回第一章修改并重新接受，后续章应恢复为待审阅。重新核对后章、接受所有章节，展开全文预览，再点击“合成为最终成果”。应得到一个包含各章的成果，可在原有工作台继续编辑、保存和导出。
6. 回长文项目重新打开最终成果，不应重复创建同名副本。删除项目时确认提示，已合成成果应保留。

## 本期边界

- 一个项目 1–12 章，每章建议 100–5000 字；模型不保证精确字数。逐章生成、逐章审阅，事实摘要由你确认。
- 已接受章节再次生成时，原正文作为修改基础进入发送清单；后章只使用前章摘要，不自动重复发送前章全文。
- 改变目标、资料或大纲后，需要重新确认和复核。合成后的项目保持记录，后续修改在成果工作台完成。
- 引用“已核验”表示来源身份、授权、内容版本和定位有效，不代表每句话已通过事实审查。写作质量仍取决于实际模型；工程流程测试使用的固定响应不能证明模型质量，真实模型评测另见执行记录。
- 停止/退出后不自动重新请求模型。服务商已执行的请求仍可能计费；重试由你主动发起。
