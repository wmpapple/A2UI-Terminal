# M3 产品功能验收

本轮只验收 M3 的产品功能和使用体验。代码、权限、冲突保护、自动化测试和构建由代理完成。

可直接运行 `logs/m3-inline-ai-review/a2ui-terminal.exe` 验收；该程序已通过隔离启动冒烟测试。也可以继续使用 `npm run desktop:dev` 验收当前源码。

## 1. 工作区文件行内修改

1. 打开已授权的 Markdown 或 TXT 文件，等待“已保存”。选中一段连续文字。
2. 选区上方应出现“润色、缩短、扩写、专业、自然、语法、翻译”和自定义修改入口。
3. 点击“润色”。非敏感本地处理应直接生成；云端检测到敏感内容时才要求额外确认。
4. 原编辑流中应显示“原文 / AI 建议”，此时文件正文和版本历史都不应改变。
5. 点击“接受”，正文只替换刚才选中的位置；点击工具栏撤销，应恢复原文。

## 2. 成果行内修改

1. 从“成果”打开一个 Markdown/TXT 文档成果，切换到“编辑”。
2. 选中文字并执行任一行内动作，确认建议卡在成果编辑器内出现。
3. 接受后打开历史版本，应只新增一个版本；使用“撤销”应恢复接受前内容。

## 3. 关闭与重新生成

1. 生成建议后点击“关闭”，正文和版本历史不应变化。
2. 再次生成并点击“重新生成”，旧建议应被替换，正文仍不应变化。
3. 只有点击“接受”才写入一个新版本。

## 4. 失效与冲突保护

1. 选中文字后先继续输入，使文档处于未保存状态，再点击行内动作；程序应要求先保存并重新选择。
2. 建议出现后修改正文、切换文件/成果或切换模型，旧建议不得继续应用。
3. 对含有两处相同句子的文本只选择第二处，接受后只能修改第二处。

## 5. 发送范围

生成时的清单或敏感确认应表明只发送当前选区。普通低风险选区修改不应要求确认完整文件、资料库、资料包或最近对话。

反馈时请说明：使用的是工作区文件还是成果、选择的动作、实际表现和期望表现。确认 M3 通过并明确授权后，才会开始 M4。
