## 实现范围

- 保留 F0 旧解析契约，增加 `local-located-v2`：MD/TXT 行范围、DOCX 实际 XML 段落（空段也计数）、PDF 文本层实际页、CSV/XLSX 工作表与行列。扫描 PDF 仍需 OCR；无法可靠定位时采用明确标记的来源级定位。
- 新导入的个人资料使用结构解析；旧资料在打开资料库后逐份补提取。每份提交进度，支持暂停、继续、重启后续做及重试失败项。数据库迁移不解析原文件，失败保留资料副本。
- schema 23 保存片段、请求/Manifest 引用映射、成果或消息内容快照绑定及审阅来源绑定。`[S1]` 只在一个请求内有效，编号在预算与检索选择后分配，最多 64 个。未选择、未发送、内容与可信来源不符的文本不获得已核验引用。
- 生成与聊天使用同一套来源标记，模型只返回编号，不能提交来源路径或自行创建可信映射。引用展示区提供一键读取本机原文、位置和重新核验；点击预览时重新检查来源。
- 成果复制携带原快照绑定；正文修改（包括 Inline）使保留的引用待核验。采用保守的整份正文 Hash 校验，任何正文变化都需要重新核验，不猜测被改写句子的语义。不同请求即使生成相同正文，也按成果版本保留独立绑定；恢复历史版本后重新检查来源授权和版本，仅有正文且请求关系不唯一时不得追认来源。
- 会话删除不删除独立成果的引用映射；来源删除清理可读片段并保留最小失效标记。来源撤权、缺失、变化与未知编号分别展示。既有成果和聊天的独立摘录不自动改写。
- 导出校验所选成果版本，并追加可读的来源标题、位置和状态，不输出内部请求 ID 或真实来源路径。
- Excel 工作表名称按 workbook 关系对应真实 XML，避免重排后名称错配；缺少可靠关系的旧式文件明确降级。旧资料补提取及来源核验均使用后台线程；一次核验内对同一来源版本只读验一次，避免多页引用重复解析整份 PDF。
- 工作区文件型成果与托管成果均保存全文生成的引用绑定。补测同时修复已有正文的工作区成果误用空文件首次写入流程的问题：受控生成使用后台读取的目标及 Hash，原有模型 `replace_empty_file` 仍只允许空文档。

## 核验含义与边界

“来源已核验”只证明来源身份、实际发送范围和版本一致，不证明某句话确实由原文支持。模型事实支持率与引用覆盖率仍需独立 Eval；评测任务和评分口径见 `evals/citation/README.md`。本轮网络测试只使用本机测试 SSE 服务，不调用用户配置的收费 Provider。

旧成果没有持久化请求绑定时，其文字中的 `[S1]` 显示为未知引用。不会追认历史编号。旧资料补提取不偷偷更新原始文件，也不把旧版来源映射成新内容。
