# M1-B 成果 AI 生成实施记录

基线：`2be46c0`（M1-A 个人资料库，用户已验收）。2026-09-23 用户授权 M1-B，并明确选择 BYOK + 本地模型，暂不提供内置服务。决策详见 [M1B_AI_ACCESS_DECISION.md](M1B_AI_ACCESS_DECISION.md)。

## 实现

- 新增 Rust `application/generation.rs`，复用聊天的 HTTP/SSE、超时、取消与错误映射。新增 `plan_generation` / `start_generation` 两个受限命令，同步 IPC、Gateway、capability 和注册验证。
- 目标只能是可信读取的单个文档成果或已回答完毕的任务。使用目标所属工作区的受控会话；不复用另一个界面工作区的活动会话。前端不能指定待写正文或任意文件路径。
- 当前成果正文默认不发送。个人资料及资料包由后端按 ID 读取，生成前消费一次性、已确认的 Manifest，并复核目标、来源及 Provider 配置。切换配置撤销旧规划，不自动切换服务，不自动重发。
- 提案生成完毕先存入 Review。Result 全文修改按 hash 检测冲突；只有接受后才写入。管理成果的版本与 Review 状态一起提交，文件失败沿用现有补偿路径。重启可恢复审阅记录，撤销复核应用后 hash；冲突支持保留原文或另存副本。
- schema 21 只追加迁移，不修改旧迁移。任务审阅关联 `task_id`，通过数据库约束保持目标工作区一致；任务依次进入 ready → review_pending → completed，拒绝/失败/撤销回到 ready。离线结构草稿入口保留，不调用模型。
- 成果助手与首页任务复用 `GenerationPanel`：模型、要求、资料选择、发送确认、流式预览、停止、拒绝、接受和撤销。云端 BYOK 沿用系统凭据保管；loopback 模型支持无鉴权空 Key。

## 范围与验证边界

本阶段支持 Markdown / TXT 文档正文生成与全文审阅，不实现 M3 选区 Inline Edit，不提前实现 M2 写作偏好/Composer/Eval，也不提供 M4 精确引用定位。模型输出视为候选正文，需用户核对事实；不将生成正文中的路径或操作文本当作写入权限。

Web Mock 显式标注模拟内容，仅验证界面流程。Rust 测试使用实际 loopback HTTP/SSE 测试服务并注入测试密钥，不读取用户真实凭据，不向外部模型发送用户资料。这能验证传输和审阅边界，不能替代真实模型的写作质量评测。

本阶段沿用单次待确认规划机制，新规划会使旧规划失效；不声明支持多个写作任务并行。进程中断时不会自动恢复或重发未完成的模型请求；已完整生成并存入 Review 的提案可以恢复。

## 产品验收修正：SiliconFlow 推理模型正文超时

2026-09-23 用户使用 `Qwen/Qwen3.5-35B-A3B` 多次总结时得到 `PROVIDER_STREAM_IDLE_TIMEOUT`。该错误证明服务已返回响应头，但连续 60 秒没有 `content` 正文；SiliconFlow 推理协议会把思考过程放在独立 `reasoning_content` 字段，现有正文安全期限按设计不把隐藏思考当作可用正文。资料仅约 263 个字符，因此不是上下文容量问题；鉴权、模型不存在和限流也有其他明确错误码。

请求体现在仅对 `silicon_flow` Provider 显式传入 `enable_thinking: false`，让写作、总结和交互请求直接生成可审阅正文。DeepSeek、OpenAI、自定义及本地 OpenAI-Compatible 请求不增加该供应商参数。保留连接、响应头、有效正文空闲和总时长原有安全期限；Provider 真正无响应时仍会超时，不用思考流量掩盖卡死。
