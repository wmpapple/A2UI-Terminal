# S4.5 性能与可访问性验证记录

> 日期：2026-09-18（Asia/Shanghai）  
> 范围：只验证 S4.5；不代表 S4.6 已开始。  
> 结论：实现与自动验证完成，等待 Windows Desktop 人工验收。

## 1. 实现范围

- 新增三个固定性能预算：`homeInteractive` 2500 ms、`resultOpen` 1000 ms、`requestFeedback` 300 ms。
- 计时从真实操作开始，到首页恢复状态读取完成、成果内容完成加载并提交下一帧、或反馈界面提交下一帧结束；失败时不会伪造成功样本。
- 测量只存在于当前 WebView/浏览器内存中的 `window.__A2UI_PERFORMANCE__`，字段只有指标名、毫秒数、预算、是否达标和时间，不含正文、标题、文件名、路径、身份或 Provider 信息，也不上传。
- 成果列表首批只渲染 40 项，每次按需增加 40 项；卡片同时使用 `content-visibility: auto`，避免大列表一次性创建全部界面。
- 应用顶部增加“跳到主要内容”；路由或成果切换后焦点移动到主要内容容器。加载和保存状态提供 `aria-busy`、`role=status` 与可读文字。
- 焦点环扩大为 3 px；普通、弱化、强调、主色和焦点色在白底的对比度均不低于 4.5:1。支持 `prefers-reduced-motion` 和 Windows 强制颜色模式，状态继续显示文字而不只依赖颜色。
- 浏览器 E2E 初始化由两次导航收敛为一次，并保留同一测试内刷新后的本地偏好，减少测试自身的启动开销。

## 2. 性能测量记录

命令：

```powershell
npm run test:e2e -- e2e/performance-accessibility.spec.ts --workers=1 --retries=2
```

最终全量 E2E 同轮输出：

| 指标               | 预算    | 测量值   | 结果 |
| ------------------ | ------- | -------- | ---- |
| 首页可交互         | 2500 ms | 289.7 ms | 通过 |
| 点击后出现明确反馈 | 300 ms  | 11.7 ms  | 通过 |
| 打开普通文本成果   | 1000 ms | 33.9 ms  | 通过 |

这组数值是固定机器上的 Chromium Web Mock 可复现基线，不冒充 Windows WebView2/真实磁盘数据。Desktop 的迁移、恢复状态读取和真实成果打开仍须按人工验收单记录；运行时代码使用同一计时器，可在开发者工具读取本次 Desktop 样本。

## 4. 已知环境限制

- 本机此前 Rust 编译曾出现内存/栈崩溃；本轮 Chromium 在页面导航阶段也偶发 `Page crashed`。这些失败发生在业务断言前，使用项目 CI 的两次重试策略后 13 条 E2E 均通过；S4.5 新用例最终一次执行首轮通过。
- 构建仍提示主 JavaScript chunk 约 1.38 MB（gzip 约 446 kB）。当前可交互基线达标，本阶段没有为追求体积数字而拆改编辑器/语言包；后续若真实 Desktop 冷启动不达标，应以分析产物建立独立修正，不得隐藏加载状态。
- 自动化不能替代 Windows Narrator、200% 缩放、强制颜色和真实 WebView2/磁盘计时，因此 S4.5 仍是“待人工验收”，不是已完成。

## 5. 数据与边界

- 无数据库 migration、IPC、Tauri Capability 或 Rust 命令变化。
- 未修改审阅、恢复、授权或导出安全规则。
- 性能样本不写入 SQLite、文件或产品遥测；关闭窗口即结束本次内存记录。
- 长列表按需渲染只影响展示数量，不截断仓库返回的数据，也不改变成果排序或内容。
