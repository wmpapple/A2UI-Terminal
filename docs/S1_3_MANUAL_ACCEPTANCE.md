## 1. 验收目标

确认 S1.3 已形成稳定、可理解且不削弱安全边界的应用外壳：

1. 应用提供首页、成果、模板、工作台、设置五个入口。
2. 新用户默认进入简单模式，不需要理解文件树、会话、Provider 或协议术语。
3. 简单模式隐藏文件树和会话列表，但必须保留“选择文件”和“新对话”两个核心入口。
4. 简单模式继续隐藏 A2UI Inspector、Provider/Model、Endpoint 和 API Key 等技术信息；专业模式保留已有 V1 三栏工作台、会话列表、Inspector 和 Provider 高级参数。
5. 两种模式共享同一份业务状态、Gateway、IPC 和 Rust 安全内核；切换模式不丢数据、不复制业务对象、不改变授权或审阅规则。
6. 模式偏好可在重启后恢复；本地存储不可用时安全回退到简单模式，且当前会话仍可切换。

## 2. 本阶段边界

以下内容是后续阶段能力，不属于本次验收失败：

- 首页的三步新手引导、六类任务入口、统一拖入区和最近成果属于 S1.4。
- 成果列表、模板选择、成果级新建、保存状态、导出入口和大众版成果工作台属于 S1.4/S1.5 及后续步骤。
- 内置试用模型、真实模型供应和额度方案受 O-08 决策约束。
- 产品安装包名称、应用标识和正式升级迁移在 S4.8 统一；S1.3 只更新应用内大众界面名称“A2UI 工作台”。

因此，当前首页、成果和模板页面显示清晰的占位说明属于预期行为，不能把占位数据伪装成真实业务能力。

## 3. 验收环境

### 3.1 推荐环境

- Windows 10/11，窗口不小于 `1000 × 650`。
- Node.js 22、npm 10/11。
- 桌面验收使用 `src-tauri/target/debug/a2ui-terminal.exe`。
- 确认没有另一个 A2UI Terminal 实例占用本地数据或开发端口。

### 3.2 启动方式

Web Mock 验收：

```powershell
cd D:\A2UI\A2UI-Terminal
npm run dev -- --host 127.0.0.1 --port 4173
```

浏览器打开 `http://127.0.0.1:4173`。Web Mock 不读取本地文件、不连接真实 Provider，适合验证导航、双模式和状态连续性。

桌面验收：

```powershell
cd D:\A2UI\A2UI-Terminal
.\src-tauri\target\debug\a2ui-terminal.exe
```

Provider 高级参数必须在桌面版验证；Web Mock 打开高级设置时只显示“不会连接真实 Provider”的安全提示，这是预期行为。

### 3.3 验收前准备

为了验证“首次默认简单模式”，请使用新的浏览器配置，或仅在 Web Mock 开发者工具中删除 Local Storage 的 `a2ui.experience-mode.v1` 后刷新。不要清除真实桌面业务数据。

## 6. 代码结构验收结论

本轮静态审查结论：**通过**。

- `AppShell` 只创建一组 `WorkspaceLayout`、`WorkspaceSidebar`、`EditorPane` 和 `ChatPanel`；没有简单版/专业版两套业务组件树。
- `professional` 只下传为 `showLeftPanel`、`showInspector` 和 `professionalTools` 等展示属性。
- 简单模式的“选择文件”直接复用 `selectContextFiles` 授权链路，“新对话”直接复用 `createSession`；没有新增文件读取、会话存储或安全分支。
- 模式偏好模块不依赖 Zustand、Desktop API 或 Gateway，不会接触 Result/Task/Review 数据。
- React 页面组件不直接导入 Desktop API 或 Gateway；feature store 继续通过 controller 访问平台层。
- `useAppStore` 仍是小型组合根，没有把 S1.3 导航或模式状态堆入业务 Store。
- Provider 高级参数仍封装在 `ProviderSettings`；简单模式没有打开该组件的入口，切回简单模式也会关闭已打开的高级设置。
- 路由采用有限集合，未知 Hash 回退首页；模式偏好只接受明确的 `professional`，其他值均回退简单模式。
- 本轮增加了存储异常防护：Local Storage 读取失败默认简单模式，写入失败不会阻止当前会话切换。

对应自动结构约束位于 `src/stores/architecture.test.ts`，模式与路由单元测试位于 `src/app/shellPreferences.test.ts`。

## 8. 缺陷分级与验收规则

- **阻断**：默认不是简单模式；简单模式泄露 Key/Endpoint/原始协议；切换丢失业务数据；专业模式绕过上下文确认、Review 或 Rust 校验；应用无法启动。
- **严重**：五入口有任一不可达；简单模式无法选择文件或创建新对话；专业工具无法恢复；模式偏好无法正常持久化；最小支持窗口无法操作核心入口。
- **一般**：文案、对齐、焦点或翻译问题，但不影响完成验收路径。
- **非缺陷**：首页/成果/模板暂无真实业务列表；Web Mock 不展示真实 Provider 表单；安装包仍使用旧发布标识。这些分别属于后续 S1.4/S1.5、运行时安全边界和 S4.8。

通过规则：S13-M01 至 S13-M13、S13-S01 至 S13-S04 必须通过；S13-M14 若受测试环境限制可记录为不适用，但正式桌面发布前必须通过。不得遗留阻断或严重缺陷。
