# 空间画布需求文档

## 1. 依据与定位

依据 [画布讨论的最后一轮](https://chatgpt.com/s/t_6ac27e39f1f881918e01f910deaedac1) 及本次补充。画布是工作区中的自由编排空间，类似流程图编辑器或 PPT 页；节点的位置、尺寸和连线承载信息。它不是纵向卡片列表，也不是顶层导航页面。

**设计原则**：Spatial First（空间位置由用户决定）；Creation Anywhere（在当前视口任意位置创建）；AI 只提出内容和关系建议，用户决定是否添加；打开画布不会将整张画布自动加入 AI 上下文。

## 2. 当前项目中的位置

- 工作台左侧资源切换增加「画布」，与「文件」「我的工具」并列。画布列表在此展示、创建、打开、重命名、删除；按当前文件、当前文件夹和独立画布区分。
- 画布打开为工作台中央的工作项标签，可与文件、工具、成果标签切换；右侧继续沿用助手区域。顶层导航保持现有结构。
- 文件工作区的文件/文件夹入口提供「打开画布」：有已关联画布时选择打开，无画布时创建并打开。当前文档编辑区也有显式入口。文件夹关联以工作区相对路径表示；独立画布不要求文件绑定。
- 画布和节点随当前工作区持久保存；切换工作区后显示对应画布。绑定文件被移走时保留画布，显示来源不可用。

## 3. 用户流程及验收条件

### 3.1 创建与管理

用户能创建独立画布、文件画布、文件夹画布；能修改标题、切换或移除关联、删除画布。删除需确认，仅删除画布及其节点、连线，不删除关联文件。列表展示关联对象和更新时间。同一文件/文件夹允许多张画布，入口应优先打开已存在画布并允许再新建。

### 3.2 空间编辑

- 初始画布为空白、占满中央编辑区；可平移、缩放、适应内容、回到 100%，有缩放比例和缩略图。滚轮平移，Ctrl/⌘+滚轮缩放，空格+拖动平移，触控板双指与捏合遵循画布引擎行为。
- 节点可自由拖动、调整宽高，坐标、尺寸、层级、视口均保存；重新打开后位置不变。支持多选与整组移动；网格吸附和整理布局（至少自动、水平、垂直、网格）。不自动重排已有节点。
- 固定顶部工具栏含选择/平移、添加、AI 生成、连接/布局动作；双击空白处在点击位置添加；固定悬浮添加按钮；组件库可搜索并拖入当前画布。添加不是追加到末尾。
- 节点具有统一标题、编辑/复制/删除/锁定等操作。文本可在节点内编辑；未编辑时以紧凑预览显示，长内容可展开。删除节点一并清理相关连线。支持撤销/重做与画布内搜索。
- 用户可连接任意两个节点，删除连线、设定标签及语义（关联/支持/反驳/来源/延伸/前置/因果/包含）。连线跟随节点移动。支持可移动、可调整大小、可改标题的分组 Frame，移动 Frame 带动组内节点。

### 3.3 内容与 AI

- 初版节点：笔记、引用、AI 摘要、图解/流程图、清单、工具。支持将已有成果、场景工具、文件作为关联节点；结果与操作卡片可沿同一节点协议扩展。
- 可粘贴文本、Markdown 和应用已有 A2UI 组件 JSON；展示安全预览并允许编辑原始内容。图解节点支持 Mermaid 源码与渲染。引用节点可保存原文、文件路径与页码，点击来源打开文件。
- AI 生成是独立动作：基于用户明确选择的当前文档/内容生成结构摘要、方法流程、核心贡献、问题清单、实验计划等；先预览，再由用户决定添加到画布。生成的节点记录来源标识与版本/哈希；来源变化时显示过期状态并允许重新生成，绝不自动覆盖手工编辑。无 AI 配置时仍可使用完整手动画布。
- 文件夹画布记录文件集合，变化时显示提示，由用户选择确认变化或触发 AI 更新概览。画布节点不会因为打开画布而进入 Context Manifest；AI 生成只使用用户在生成弹窗明确确认的来源文件。

## 4. 数据与实现约束

- `Canvas`: id、workspaceId、title、binding（none/file/folder/result 与关联路径；文件夹含文件快照）、viewport(x/y/zoom)、createdAt、updatedAt。
- `CanvasBlock`: id、type、x/y/width/height、zIndex、title/body、sourcePath(s)、sourceHash、parentFrameId、locked、createdAt、updatedAt。节点属于一张画布；来源是否过期可由保存的哈希或文件集合与当前状态推导。
- `CanvasEdge`: id、canvasId、sourceBlockId、targetBlockId、relation、label。
- 桌面端使用现有 Tauri + SQLite 命令与迁移体系持久化；浏览器 mock 维持相同语义。读写需要工作区范围校验、类型/尺寸/数据长度校验；批量保存必须原子化，避免部分节点遗失。旧版画布数据若存在，迁移时保留内容并转为空间节点；旧版未绑定工作区的画布归入最近使用的工作区。
- 前端采用 React 节点画布引擎承载拖动、缩放、连线、尺寸调整、缩略图；节点内容可复用项目现有 A2UI/工具/成果组件。保存状态有可见反馈，失败后保留未保存内容并可重试。

## 5. 验证清单

1. 独立、文件、文件夹画布的创建、重命名、删除、重新打开与工作区隔离。
2. 拖动、缩放、平移、调整大小、多选、连线、Frame 和视口恢复；刷新和重启桌面应用后数据保持。
3. 顶栏、双击、悬浮按钮、组件库拖入四种添加路径；文件工作区入口和工作台三栏定位。
4. 手工内容、引用打开来源、图解预览、工具/成果/文件关联；AI 预览、来源变化、无配置场景；Context Manifest 不因画布打开而变化。
5. 类型检查、单元/集成测试、桌面构建及真实交互检查。

## 6. 后续扩展边界

原讨论也提出文档选区直接拖入、PDF 精确页码定位、等间距参考线、思维导图自动布局、Frame 折叠、结果卡片内嵌编辑等建议。本轮数据结构保留来源、页码、Frame 归属和可扩展节点类型；这些深度联动不作为当前版本的验收前提。当前版本以用户明确要求的空间画布及工作台集成为主。
