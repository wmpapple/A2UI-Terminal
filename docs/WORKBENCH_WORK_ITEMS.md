# 工作台 WorkItem 约定

工作台是打开和操作工作对象的统一空间，不是文件编辑器的别名。

## 对象边界

| 对象 | 职责 | 持久化 |
| --- | --- | --- |
| 工作区文件 (`document`) | 当前工作区的来源文件 | 工作区文件与文件历史 |
| 我的工具 (`tool`) | 持续填写的工具实例 | 工具实例状态 |
| 长文项目 (`project`) | 目标、资料、大纲、章节及审阅进度的持续容器 | WritingProject 与章节草稿 |
| 项目章节 (`project-section`) | 单章写作与审阅视图，隶属于长文项目 | 复用 WritingProject 的章节及草稿，不另建副本 |
| 成果 (`result`) | 用户主动确认的稳定输出 | Result Revision |
| 画布 (`canvas`) | V3 扩展点 | 尚未实现 |

左侧“文件 / 我的工具 / 项目”只切换浏览列表，不关闭或激活中间的标签。中间可同时打开不同类型的 WorkItem；激活的标签是工作台唯一的当前对象，右侧 AI 的标题、上下文和快捷任务跟随它。关闭标签只关闭视图，不删除底层对象。删除项目或工具须使用各自明确的删除操作。

## 统一外壳

文件、工具、项目与项目章节共用 `WorkItemFrame` 的标题和对象导航规则：已打开标签在顶部，下面依次是对象标题、类型与状态、对象级导航，再进入内容。标题区最小高度、状态 Badge、导航分隔线和水平内边距由共享组件控制；右侧 AI 始终跟随激活标签。文件提供编辑或阅读、审阅、交互视图；工具提供填写、关联与核对、成果；项目保留概览、目标与资料、大纲、正文与审稿阶段。内部编辑器、工具表单与项目流程保持各自实现，未来画布也应复用此外壳。

首页只提供“开始长文项目”和继续最近项目；项目的长期浏览、搜索和重开位于“工作台 > 项目”。旧 `#projects` 入口进入工作台的新项目视图，不再形成独立页面。

项目 Tab 保留概览、目标与资料、大纲三个阶段；确认大纲后，章节以独立 WorkItem Tab 打开。项目 Tab 与章节 Tab 可并存，关闭章节 Tab 不删除章节。项目列表第二行显示阶段与实际更新时间。删除项目收在项目标题的更多菜单中。

## 项目与成果

项目首次完成章节审阅后，由用户点击“保存为成果”创建独立 Result。后续项目修改不自动写入成果；项目与已发布修订不一致时显示“项目内容比成果更新”，用户再次完成章节审阅并点击“更新成果”才保存新的 Result Revision。更新前检查成果内容 Hash 和未保存草稿，避免覆盖成果页的独立编辑。项目删除不删除已创建的成果。

项目 AI 默认使用项目目标、大纲和已接受章节摘要；章节 Tab 额外包含当前章节内容，仅纳入前文已接受章节的摘要。项目资料由 Context Manifest 列出并在发送前确认。普通模式的确认弹窗列出实际包含的项目内容、资料、写作偏好和处理位置；技术清单仅在专业模式展开。AI 提供建议，不直接写入项目；章节生成仍走项目自己的计划、确认和审阅流程。
