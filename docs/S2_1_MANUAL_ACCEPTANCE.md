# S2.1 统一导入批次与格式能力人工验收

> 状态：主窗口原生拖放已迁移至正确的 Tauri WindowEvent 通道，待重新人工验收
>
> 对应计划：`V2_IMPLEMENTATION_PLAN.md` S2.1 / LOG-0042—LOG-0053
>
> 验收边界：只验收 ImportBatch、文本/DOCX/PDF 能力确认和导入安全；不验收 S2.2 的 CSV/XLSX 结构化解析或图片多模态理解。

## 1. 验收准备

建议使用不含真实个人信息、密钥或公司机密的可丢弃测试文件：

1. 小于 2 MB 的 UTF-8 `.md` 或 `.txt`。
2. 有普通正文、可正常打开且小于 25 MB 的 `.docx`。
3. 有可选中文本层、可正常打开且小于 25 MB 的 `.pdf`。
4. 一个扫描型 PDF，或没有文本层的 PDF。
5. 小型 `.csv`、标准 `.xlsx`、有效 `.png`/`.jpg`。
6. 一个不支持的文件，例如 `.exe` 或 `.bin`。
7. 只用于验证拒绝规则的空白 `.env`、`id_rsa` 或 `.pem` 测试文件；不要使用真实密钥。

真实桌面验收建议记录应用版本、HEAD、Windows 版本、数据库 schema（应保持 v10）以及测试文件是否均为虚构/脱敏资料。自动化已经覆盖超限、无效 Office 包、Zip Bomb 和确认前替换；人工无需打开或传播未知恶意样本。

## 2. 功能验收

### S21-M01 系统选择与确认页

1. 从首页“添加资料”点击“选择资料”。
2. 同时选择 UTF-8 文本、DOCX、PDF、CSV、XLSX、图片和不支持格式。

预期：先出现“确认读取范围”，不会直接进入工作台或直接把全部文件标成已授权。页面逐项显示文件名、大小、能力、原因、替代方式和警告，不显示绝对路径。

### S21-M02 当前可读能力

预期：

- UTF-8 白名单文本显示“可读取和编辑”，默认勾选。
- 有正文的 DOCX/PDF 显示“只读文本”，默认勾选。
- DOCX/PDF 明确提示复杂版式、公式、图表、扫描页不会无损复刻。
- DOCX/PDF 确认后能在工作台打开提取正文；来源文件没有被修改。

### S21-M03 CSV/XLSX 能力诚实状态

预期：CSV/XLSX 被识别为表格能力，但显示适配器待开放、不可勾选；页面提供转换/等待下一阶段等替代方式。不得显示“已解析”“已分析”或虚构表格内容。

### S21-M04 图片能力诚实状态

预期：有效 PNG/JPEG/GIF/WebP 被识别为图片上下文，但显示 S2.2 待开放、不可勾选；明确说明当前不会只提取文字来假装理解图片，也不会把图片发送给模型。

### S21-M05 不支持格式替代方式

预期：不支持格式显示“不支持”、不可勾选，并给出转换为 UTF-8 文本、DOCX 或带文本层 PDF 等可执行替代方式；其他可读文件仍可继续确认。

### S21-M06 扫描 PDF / 无文本层 PDF

预期：检查阶段即显示没有可提取文本层或读取失败，不可勾选，并建议使用带文本层 PDF 或后续 OCR/视觉能力；确认时不会把它静默当作空文档。

### S21-M07 逐项缩小读取范围

1. 取消勾选一个原本可读的文本或 DOCX。
2. 确认加入资料。

预期：只有仍勾选的可读文件进入工作区；被取消项、CSV/XLSX、图片和拒绝项均不进入文件列表或上下文。

### S21-M08 取消零授权

1. 重新选择若干文件。
2. 在确认页点击“取消”。
3. 重启应用并检查最近工作区/资料。

预期：取消后没有新增文件或独立工作区授权；重启不会恢复该待确认批次。

### S21-M09 Windows 桌面原生拖入

1. 完全停止修复前的 `npm run tauri dev` 及桌面程序，重新运行当前工作树的 `npm run tauri dev`；无需先制作或安装安装包。
2. 从 Windows 桌面或资源管理器把一个 UTF-8 测试文件直接拖到首页资料区并放开。
3. 取消确认页，再分别把一个小型 `.csv` 和标准 `.xlsx` 拖到首页资料区。
4. 取消确认页，再把同一文件拖到首页资料区之外并放开。

预期：拖到资料区时不再弹出系统选择器，也不能完全无响应，而是立即出现该实际文件的“确认读取范围”页面；仍需明确确认后才建立授权。CSV/XLSX 也必须进入确认页，但应显示已识别、表格适配待开放且不可勾选，不能声称已读取。绝对路径只由 Rust 原生拖放事件接收，前端不读取浏览器 `DataTransfer` 路径或正文，也不能绕过格式、大小、敏感路径和确认时重检。

预期补充：拖到资料区之外不出现确认页、不建立批次。主窗口必须通过 Tauri `WindowEvent::DragDrop` 接收原生事件；不得改回只适用于子 WebView 的 `WebviewEvent::DragDrop`。

开发模式补充预期：React StrictMode 的挂载清理检查不得使资料区失去注册；旧 Effect 的异步注销只能删除旧目标，不能删除当前目标。开发版与安装版在原生拖放能力上应一致。

### S21-M10 批次摘要与限制

预期：确认页显示文件数、批次大小、单批最多 20 项和总计 100 MB；单个文本、文档、图片的能力说明分别遵守 2 MB、25 MB、20 MB 上限。

### S21-M11 重复选择

两次选择同一个已经授权的可读文件并确认。

预期：不会创建两个不同授权副本，不修改来源文件；工作台仍能打开同一虚拟文件。

### S21-M12 专业模式兼容路径

切到专业模式，从文件树区域使用“添加文件”。

预期：既有入口仍可选择文本/DOCX/PDF并打开，且同样拒绝敏感、超限、无效和危险 Office 文件；不会因专业模式绕过安全规则。

### S21-M13 失败可恢复

在确认前移动或删除一个已选择文件，或用无效内容替换测试文本，然后点击确认。

预期：Rust 提示文件在确认前发生变化并停止本批导入；已经存在的工作区文件不受影响，来源文件不被覆盖。

### S21-M14 Web Mock 确定性

运行 `npm run test:e2e` 或在 Web Mock 中选择资料。

预期：显示固定的文本、DOCX、XLSX、图片和敏感文件能力样例；确认只加入两个可读样例，不调用桌面 IPC 或真实文件系统。

## 3. 安全与隐私阻断项

以下任一失败均视为 S2.1 验收不通过：

### S21-S01 绝对路径不出现在前端

确认页、错误提示、DevTools 状态和正常诊断中不得出现 `C:\...` 等绝对路径。前端只能获得批次/item ID、文件名、虚拟路径和 `sourceId`。

### S21-S02 隐藏与敏感路径默认拒绝

点文件、Windows Hidden 属性文件、`.git`、`.ssh`、`secrets`、`.env*`、常见私钥/证书/凭据文件不可勾选，不建立授权。使用虚构空白测试文件，不要测试真实密钥。

### S21-S03 确认前零持久化

在确认前取消或退出应用，SQLite 不应新增 `workspace_files` 授权；ImportBatch 不写入 SQLite、localStorage、日志或遥测。

### S21-S04 来源文件只读

选择、检查、取消和确认均不得改写、重命名、移动或删除来源文件。可在验收前后比较文件 Hash/修改时间。

### S21-S05 Office 压缩安全

自动化安全 fixture 必须证明：路径穿越条目、超过 2000 个条目、单条目超过 25 MB、总展开超过 100 MB或压缩比超过 100:1 的 DOCX/XLSX 被拒绝。不得为人工验收运行未知来源恶意文档。

### S21-S06 宏与外部链接不执行

含宏标记、外部关系、嵌入对象或图表的 Office 文件只显示警告或只读/待适配状态；不得执行宏、访问外部链接、加载远程资源或无损回写。

### S21-S07 确认时重新检查

文件在选择后被替换、变为无效 UTF-8/危险包或膨胀超限时，确认必须失败且不建立该批授权，不能信任旧检查结论。

### S21-S08 无内容外发

S2.1 不调用 Provider，不发送文档、Prompt、图片、文件名或路径，不新增遥测。网络不可用时仍应完成本地选择、检查、取消和文本/DOCX/PDF 确认。

### S21-S09 最小 Capability

主窗口只新增：

- `select_import_sources`
- `inspect_import_batch`
- `set_import_drop_target`
- `core:event:allow-listen`
- `core:event:allow-unlisten`
- `confirm_import`

不得新增 `core:event:allow-emit`、`core:event:allow-emit-to`、shell、任意文件系统、网络、数据库查询或批量删除权限。

### S21-S10 数据库兼容

数据库 schema 保持 v10；升级前已有 Result、Task、Workspace、版本和 A2UI 历史仍可读取。S2.1 不应为短生命周期 ImportBatch 制造新表或迁移。
