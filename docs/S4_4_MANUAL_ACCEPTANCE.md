# S4.4 崩溃恢复与迁移全链路人工验收

> 范围：只验收 S4.4；通过前不得开始 S4.5。

> 必须使用 Windows 桌面应用。测试强制结束进程前，请只使用不含敏感信息的临时成果，并先保存其他应用中的工作。

## 准备

1. 完全关闭旧桌面应用和开发进程。
2. 在项目根目录执行 `npm run desktop:dev`，确认可正常进入首页。
3. 新建一个 Markdown 测试成果，正文使用 `S4.4 恢复测试`，不要使用真实业务内容。

若再次遇到随机 Rust 编译崩溃，在新的 PowerShell 会话使用：

```powershell
(Get-Process -Id $PID).ProcessorAffinity = 1
$env:RUSTUP_TOOLCHAIN = 'stable'
$env:RUST_MIN_STACK = '33554432'
$env:CARGO_INCREMENTAL = '0'
$env:CARGO_BUILD_JOBS = '1'
npm run desktop:dev
```

## M01 Result 未保存输入恢复

1. 打开测试成果，进入编辑模式，输入至少两行 `尚未保存的恢复内容`。
2. 输入后等待约 300 ms，但不要等到正常自动保存完成，立即关闭桌面窗口；若内容已经显示“已保存”，重新修改后更快关闭。
3. 重新启动应用并进入首页，再打开对应成果。
4. 在恢复提示中选择“恢复未保存内容”，检查内容后保存。
5. 再制造一次未保存内容，重启后改选“保留磁盘版本”。

预期：首页提示存在未保存成果；打开后必须由用户选择，不自动覆盖。恢复后内容进入编辑态并可正常保存；保留磁盘版本会丢弃恢复草稿但不删除成果或历史。

## M02 外部变化冲突

1. 再次制造一份未保存恢复草稿并关闭应用。
2. 用外部文本编辑器修改该成果对应的已授权文件；若是应用托管成果不便定位，可改用已授权工作区 Markdown 成果完成此项。
3. 重启并打开成果。

预期：恢复提示明确说明磁盘版本已经变化；磁盘正文保持外部修改，不被草稿自动覆盖。选择恢复后仍先进入可检查的编辑态，保存时继续受 Hash 冲突保护。

## M03 Task 跨崩溃与幂等

1. 从首页用“会议纪要”或“文档总结”模板创建本地结构草稿。
2. 若任务很快完成，正常打开其成果；关闭并重启应用后再次通过同一任务入口/恢复后的状态打开。
3. 检查最近成果，不要手工复制生成文件。

预期：一次 Task 最多对应一个 Result 和一个托管文件；重启不会出现标题/内容相同但 ID 不同的重复成果。自动化故障注入已覆盖“意图已记录但文件未写”和“文件已写但数据库未完成”两个不可人工稳定命中的窗口。

## M04 Review 跨重启与重复应用

1. 让 AI 对测试文档提出两处修改，进入“审阅中心”。保留第一块的勾选，取消第二块的勾选，再点击“保存选择（不应用）”。看到“选择已保存”后关闭应用。此时不要点击“应用已选修改”，该按钮会立即写入并结束本次审阅，不是只接受第一块。
2. 重启后打开原工作区，从审阅中心继续，确认第一块仍勾选、第二块未勾选，原文尚未改变。如果 AI 只返回一个修改块，先保存该块的选择验证恢复，再用两个独立修改块验证部分接受。
3. 应用一次，记录成果内容和版本数量；离开后重新打开，不要再次产生相同修改。
4. 在临时测试文档上重复请求同一修改方案（可先拒绝旧方案，或使用内容相同的另一份测试文档）。即使模型重复使用 `change-1` 等块编号，也应正常进入审阅，不出现 `local database operation failed`。若第一次已经应用，请使用仍包含旧文本的测试文档，不能要求匹配已不存在的旧锚点。

预期：Review 和逐块决定跨重启保留；应用只产生一次修改/版本。已经应用的 Review 不会在启动恢复时自动再应用，也不会重复插入正文。

## M05 Export Job 中断与目标保护

1. 导出一个较长 PDF，在保存对话框取消；重新导出并在生成/写入阶段关闭应用（短任务可能无法人工命中，可使用更长正文）。
2. 重启后查看首页恢复摘要，再检查目标目录。
3. 对中断记录重新发起一次新导出，选择新的文件名。

预期：取消显示取消；无法证明已经原子提交的旧任务标为中断，不会在重启时自动重新生成或覆盖目标。若目标字节已完整提交且 Hash 一致，只登记完成，不重复写入。界面和恢复摘要只显示文件名，不显示绝对路径。

## M06 迁移、旧数据与启动安全

1. 使用原有工作区、旧成果、历史 Review 和 Surface 启动当前构建。
2. 打开一个此前尚未成为 Result 的旧工作区文本，再查看成果列表。
3. 检查原工作区目录，没有因升级出现批量副本或文件删除。

预期：旧数据仍可读；旧文件只在显式打开时惰性建立 Result。schema v16 迁移不复制整个工作区、不删除真实文件。迁移中途失败和较新 schema 拒绝由自动故障测试覆盖；这两项不要在真实业务数据库上手工篡改验证。

## P0 明确限制

- 恢复只针对本机 SQLite 与已授权本地文件，不是云备份或跨设备同步。
- 中断导出不会后台自动重试；用户必须重新发起并再次确认目标，以避免静默覆盖。
- 首页只提供恢复摘要；具体 Result 草稿需打开对应成果后选择，Review 仍在审阅中心处理。
- 不承诺在原子文件替换已经完成后撤销该次写入；系统只会通过 Hash 将其认定为已提交，避免重复导出。

## 验收回复

全部通过后请回复：`S4.4 验收通过`。若失败，请提供 M 编号、操作发生在关闭前的界面状态、重启后提示和错误码；不要发送真实正文、绝对路径或数据库文件。
