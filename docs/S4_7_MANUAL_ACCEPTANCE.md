# S4.7 Beta E2E 与发布验收

> 范围：只验收 S4.7。全部通过后才能开始 S4.8；本单不会签名、发布或升级正式安装包。

> Web Mock 的“导出成功”只演示流程，不会生成文件。真实保存、导出、崩溃恢复和 Provider 行为必须在 Windows 桌面应用复验。

## 准备

1. 提交或备份当前真实工作；不要用重要文件做故障测试。
2. 在项目根目录执行 `npm run audit:beta-evidence`，应显示 4 类画像、4 个模板、5 类成果、8 项 12.3 准则和 15 组 P0 需求均已校验。
3. 启动桌面应用：

```powershell
(Get-Process -Id $PID).ProcessorAffinity = 1
$env:RUSTUP_TOOLCHAIN = 'stable'
$env:RUST_MIN_STACK = '33554432'
$env:CARGO_INCREMENTAL = '0'
$env:CARGO_BUILD_JOBS = '1'
npm run desktop:dev
```

4. 只在准备好的测试工作区操作。若需真实 AI 生成，使用你已配置且允许处理测试内容的 Provider；不要在截图或反馈中暴露 Key、Endpoint、真实正文或路径。

## M01 首次有效成果与四类用户

1. 在一个未完成新手引导的测试配置中启动应用，从看到欢迎页开始计时。
2. 完成或跳过引导，选择“整理一组资料”→“会议纪要”，填写“Beta 发布例会”，创建结构草稿并进入工作台。
3. 点“编辑”，写入至少一个明确结论和一个行动项，等待“已保存”，停止计时。
4. 结果必须小于等于 90 秒；只有标题或空白结构不算有效成果。
5. 回到首页依次检查：
   - 办公协作：会议纪要、周报；
   - 阅读研究：文档总结；
   - 求职/内容修改：简历优化；
   - 数据/流程搭建：“分析表格或数据”和“制作表单 / 清单 / 小工具”。

预期：四个 P0 模板都能打开；表格入口直接显示“表格（CSV）”，结构化入口只提供清单、表单和小工具，不再显示“以后开放”；首次有效成果 ≤90 秒。

## M02 两个高频场景的完成、保存和导出

分别完成以下两条，不要复用同一个 Result：

| 场景     | 输入                                   | 完成证据                | 保存证据       | 导出证据               |
| -------- | -------------------------------------- | ----------------------- | -------------- | ---------------------- |
| 会议纪要 | 主题、结论、行动项                     | Task 显示结构草稿已创建 | 工作台“已保存” | PDF 或 DOCX 可真实打开 |
| 文档总结 | 用途选“决策支持”，填写观点、事实、建议 | Task 显示结构草稿已创建 | 工作台“已保存” | PDF 或 DOCX 可真实打开 |

若使用真实 Provider 继续生成，还要确认：发送前清单可见，AI 生成失败不会抹掉已保存内容，生成出来的文件修改仍先进入审阅。记录两条场景各自的耗时、是否完成、是否保存、是否导出即可；不要记录正文和完整路径。

预期：两条场景各自形成独立 Result；保存后可从“成果”重开；导出内容对应点击导出时的已保存版本。

## M03 五类成果闭环

1. 新建 Markdown 文档，写入两段内容，保存、重开并导出 PDF。
2. 从首页“分析表格或数据”新建 CSV 表格，写入两列两行，保存、重开并导出 XLSX。
3. 从首页结构化入口分别新建清单、表单和小工具：
   - 清单增加一项并切换完成状态；
   - 表单增加一个必填日期字段；
   - 小工具只修改受控的 key/label/value 配置，不输入脚本或 HTML。
4. 保存并从“成果”重开三者；清单和表单各导出一次 JSON 或 PDF，小工具导出受控 JSON。

预期：五类成果的标题、类型、内容和保存状态正确；切换视图或重开不丢内容；小工具不会执行输入内容。A2UI Surface 协议快照若不支持便携导出，应保持禁用并给出说明。

## M04 安全红线回归

1. 给 AI 发送带资料的请求，确认首次发送前能查看具体发送清单；取消后不得发送。
2. 请求修改现有文件，确认只能先进入“查看修改/审阅中心”，接受前磁盘内容不变；拒绝后仍不变。
3. 生成一个可信交互表单，确认只渲染固定 Catalog；未知组件、非法 JSON 或任意脚本只显示可理解错误，不执行。
4. 触发高风险动作，确认显示风险、影响对象和二次确认；取消不产生副作用。
5. 打开“设置 → 隐私”，确认改进指标默认关闭、可查看字段；字段中不得出现正文、Prompt、回复、文件名/路径、图片、Key、具体 Endpoint 或身份信息。

预期：上下文、AI 写入、A2UI 和高风险 Action 均不能绕过既有门；简单模式不会把协议 JSON 或技术错误堆栈直接展示给普通用户。

## M05 错误、取消与恢复

1. 新建一个测试成果，再用相同文件名创建第二个；应明确拒绝且第一个成果仍可打开。改用新文件名重试，应成功。
2. 编辑一个成果，在出现“有未保存修改”后立即关闭并重新启动应用；按恢复提示选择恢复草稿或保留磁盘版本，各测试一次。
3. 导出时在系统保存对话框取消，再重试新文件名；已有目标选择替换时应按 S2.8 已验收语义安全替换，不残留临时文件。
4. 在审阅已保存选择但尚未应用时重启；审阅应可恢复，应用一次后不得重复写入。
5. 让 Provider 返回失败或断网后重试；错误必须可理解，已有 Result、Revision 和导出文件不被删除。

预期：失败、取消和重启不会静默覆盖、重复应用或破坏既有成果；恢复选择明确，重试从安全状态继续。

## M06 Beta 候选发布检查

1. 执行 `npm run test:e2e:beta`，确认四条 Beta 场景通过，并在 Playwright 结果中能看到会议纪要和文档总结的生命周期附件。
2. 查看“帮助/隐私/第三方声明”相关文档，确认处理位置、清理范围、诊断排除项、依赖许可证和安全联系渠道可找到。
3. 若使用 GitHub Actions 生成内部验收包，只运行 `Windows unsigned acceptance packages`，确认产物名称明确包含 `unsigned`；不要把它发布为稳定版。
4. 安装或运行候选后，用键盘完成首页 → 创建 → 编辑 → 保存 → 导出；在 200% 缩放和 Windows 高对比度下主要操作仍可见。

预期：CI 的 Beta 证据门和 E2E 均通过；内部包明确未签名；没有触发 `v*` 正式发布工作流、导入 PFX 或生成稳定更新源。

## 尚未由 S4.7 解决的发布条件

- O-06：远程匿名指标接收端、保留期和删除机制未决定；当前只有默认关闭的本机计数。
- O-08：平台内置试用模型、服务端鉴权、额度和滥用控制未实现；本地结构草稿和 Web Mock 不能冒充真实 AI 生成。
- 原 PRD：登记路径中的原文件已不存在；当前按固定 Hash 的仓库派生矩阵验收，S4.8 前应取得相同 Hash 原件复核 12.3，或由发布负责人书面接受这一限制。
- S4.8：版本/产品标识统一、Authenticode、Updater 签名、上一版升级、卸载保留和 Draft Release 尚未开始。

这些限制允许验收本地 Beta 闭环，但不允许把当前构建描述为正式签名、可公开稳定发布的版本。
