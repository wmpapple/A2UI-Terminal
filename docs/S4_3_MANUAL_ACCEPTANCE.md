# S4.3 隐私安全产品事件与 KPI 人工验收

> 范围：只验收 S4.3；通过前不得开始 S4.4。

> 必须使用 Windows 桌面应用。当前版本没有匿名指标上传接收端；本单检查的是默认关闭、本机安全计数、字段透明度和关闭清除，不应产生任何遥测网络请求。

## 准备

旧版 v14 数据库的事件白名单遗漏已通过 v15 迁移修复。必须退出旧进程并重新运行当前 `npm run desktop:dev`，由启动迁移更新数据库，再新建成果和导出。历史被拒绝的创建事件无法补回；只重新打开设置不会执行数据库迁移。

1. 完全关闭旧桌面应用和开发进程。
2. 在项目根目录执行 `npm run desktop:dev`。
3. 准备一个不含敏感信息的 Markdown 测试成果。不要为了验收输入真实姓名、邮箱、API Key、内部路径或业务正文。

本机若遇到随机 Rust 编译崩溃，可在新的 PowerShell 会话中使用：

```powershell
(Get-Process -Id $PID).ProcessorAffinity = 1
$env:RUSTUP_TOOLCHAIN = 'stable'
$env:RUST_MIN_STACK = '33554432'
$env:CARGO_INCREMENTAL = '0'
$env:CARGO_BUILD_JOBS = '1'
npm run desktop:dev
```

## M01 默认关闭与开启前透明

1. 首次进入“设置”，找到“隐私与产品改进”。
2. 确认“帮助改进产品”开关状态。
3. 在不开启开关的情况下点击“查看将发送的数据”。
4. 查看公共字段、逐事件中文说明和“永不采集的内容”。

预期：开关默认关闭，本机事件数为 0；字段字典在开启前即可查看。界面明确说明当前没有上传接收端、计数只在本机；永不采集清单包含文档正文、Prompt、AI 回复、文件名/路径、图片、API Key、Endpoint/模型 ID、身份/联系信息和本地索引内容。

## M02 首次闭环后的非打扰邀请

前提：此前没有在邀请框内点击过“暂不开启”或“主动开启”。邀请框中的选择才标记邀请已处理；单独切换右上方指标开关不再处理邀请。不要为重测清除真实业务数据。

“暂不开启”只出现在邀请框内，不是常驻按钮。只保存文档且未操作邀请时，必须出现邀请，不能因为显示“已处理”说明就跳过 M02。旧版本存在开启开关也标记已处理的问题；本次用户反馈的错误本机标记已定点修复，重新进入设置可复验。

1. 保持开关关闭，离开设置页。
2. 从成果页或工作台打开测试 Markdown，修改并成功保存（只保存恢复草稿不算）；也可以完成一次导出或应用一次已经审阅的修改。
3. 回到“设置”的“隐私与产品改进”。
4. 先点击“暂不开启”。

预期：完成动作本身不弹阻断窗口、不改变成果，也不自动开启指标。回到设置后只出现“你已经完成了一次成果闭环”的非打扰提示；选择“暂不开启”后开关仍关闭、事件数仍为 0，其他功能继续可用。

## M03 主动开启与本机计数

1. 主动打开“帮助改进产品”开关。
2. 新建一个 Markdown 成果并保存，再导出一次 Markdown 或 PDF。
3. 若方便，再完成一次任务、一次发送清单确认或一次 Review 接受/撤销。
4. 返回设置页，检查本机事件数和六项核心成果指标。

创建事件漏记修复后的复验：重启当前构建并确认指标开启，新建或复制一份成果，进入字段字典确认“成果已创建”次数增加，再导出并重新进入设置，确认“成果已导出”次数增加。重复打开同一成果不应增加创建次数。旧版本漏记的历史不会回填；不能仅凭缺少创建事件判断用户操作先后。

预期：只有主动开启后的动作增加本机事件数；保存/导出后“保存/导出率”出现样本，执行了对应流程的其他指标也出现样本。指标只显示成果率和计数，不显示 DAU、消息数或模型调用量；动作失败或指标记录失败都不能破坏成果。

M03 修订：保存/导出成功率与撤销/恢复成功率均按实际操作成功数除以成功加失败数计算，取消排除。打开任意旧成果，修改并保存、导出，再点击成果“撤销”或在版本历史恢复一个版本，重新进入设置，两项应出现样本，不依赖创建次数。工作台和独立文件保存均覆盖；未保存编辑器 Ctrl+Z 不算版本恢复。AI 审阅/修改接受率只统计 AI Review，普通手动编辑不增加这些指标。升级前没有配对结果的旧导出事件不补造样本，升级后再操作一次即可。

## M04 字段字典与内容红线

1. 再次打开“查看将发送的数据”。
2. 检查保存、导出、AI 请求、A2UI 渲染和性能事件的字段。
3. 对照刚才使用的测试成果，检查界面是否出现其标题、正文、文件名、路径或会话内容。

预期：事件只展示固定布尔结果、动作/错误/格式/处理位置类别和耗时区间；不得出现测试成果的标题、正文、文件名、路径、Prompt、AI 回复或任何业务对象 ID。技术事件名旁边有普通用户可理解的中文说明。

## M05 关闭、清除和失败隔离

1. 关闭“帮助改进产品”。
2. 确认成功提示和本机事件数。
3. 保持关闭，再保存或导出一次测试成果，然后重新进入设置。
4. 再次打开字段字典。

预期：关闭立即停止采集并把已有本机事件数清为 0；关闭后的保存/导出不增加计数。字段字典仍可查看，成果内容、保存状态和历史不受影响。

## M06 重启与无上传边界

1. 保持开关关闭，退出并重启桌面应用，确认仍为关闭。
2. 主动开启后再次重启，确认用户选择保留；执行一次测试保存。
3. 在断网状态下重复查看设置、字段字典并保存测试成果，然后恢复网络。

预期：开关选择跨重启保留；断网不会出现遥测上传失败、重试或功能阻塞，计数仍只保存在本机。界面始终显示“当前版本没有配置上传接收端”。关闭开关后应再次清零。

## P0 明确限制

- O-06 的接收端、服务端保留期、聚合和远程删除机制仍未决定；S4.3 不实现上传队列、后台发送或远程仪表盘。
- 当前 KPI 是本机固定事件计数形成的产品质量信号，不是跨设备、跨用户或商业分析报表。
- 本阶段不以 DAU、消息数或模型调用量作为核心成果指标，也不采集内容来解释失败。
