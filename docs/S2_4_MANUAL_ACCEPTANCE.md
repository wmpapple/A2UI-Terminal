## 1. 本阶段交付结论

- Rust 是唯一可信 Planner；前端不能指定策略、分块范围、检索得分或索引内容。
- 短内容使用 `Full`，长文/多来源使用 `Retrieval`，短选区或短当前文件与其他长资料组合时使用 `Hybrid`。
- 文本优先按换行和句末切分，目标约 1600 字符、重叠约 200 字符；表格使用稳定的结构化 JSON 行参与分块。
- 检索只在本机 Rust 内存运行，使用确定性词法/BM25 与中文 bigram；不下载、不调用 Embedding 模型。
- 输入预算为 32000 token，并预留 2048 token 给包装与系统指令；非 ASCII 内容使用更保守估算。最近消息最多占 6000 token。
- Manifest 展示策略、实际来源、分块数以及 `chunkId + 字符起止范围`。用户仍可取消来源或缩小选择。
- 索引正文、分块和词频不写入 SQLite、临时文件、日志或遥测。撤销授权、内容变化、切换/删除工作区、手动清除、本地数据清除和进程退出都会使相关索引失效。
- 发送前 Rust 再次验证来源仍获当前工作区授权且内容 Hash 未变化；旧清单不能越过撤销或外部修改。
- 没有新增 migration、持久正文表、Embedding 依赖、云端检索或 S2.5 Review 能力。

## 3. 功能验收

### S24-M01 短内容保持全文路径

1. 只勾选 `short.md`，输入一个与短文有关的问题并打开发送清单。
2. 确认清单显示“全文策略：短内容按原文发送”。
3. `short.md` 显示为全文来源，不显示检索分块范围。

预期：短文没有为了使用检索而被不必要切碎；`indexMode` 为 `none`。

### S24-M02 长文自动使用检索

1. 只勾选 `long.md`，问题中包含测试主题词。
2. 生成发送清单。
3. 确认显示“检索策略：只发送与问题相关的分块”和“索引不写入磁盘”。
4. 确认 `long.md` 后显示实际分块数，以及类似 `chunk-0001 [0–1600]` 的字符范围。

预期：没有把整份长文塞入请求；估算 token 不超过清单显示的 32000 预算。

### S24-M03 检索结果与问题相关且可复现

1. 对同一份未修改的 `long.md` 使用完全相同的问题生成两次清单。
2. 记录两次显示的 `chunkId` 和字符起止范围。
3. 如 Provider 可用，确认后发送并检查回答能引用测试主题附近的信息。

预期：两次范围和顺序完全一致；离线生成清单不需要 Provider、网络或模型下载。

### S24-M04 关键短内容与其他长资料使用混合策略

1. 打开 `short.md` 作为当前文件，同时勾选 `long.md`。
2. 生成发送清单。

预期：显示“混合策略”；短当前文件为全文，长资料显示检索分块范围。即使短当前文件和 `long.md` 同时出现在“项目文件”与“已授权的本地资料”中，授权资料复选框也必须真实进入 Rust 清单；同一 `sourceId` 只发送一次，不能因为前端去重而丢失选中状态。“最终发送清单”必须在生成 Rust 清单前显示已选中的 `long.md`。

### S24-M05 用户可以缩小范围

1. 在清单确认前取消 `long.md` 或其他来源。
2. 重新生成清单。

预期：被取消来源进入“不会发送/用户未选择”，策略和估算大小同步更新；取消操作不会调用 Provider。

### S24-M06 手动清除内存索引

1. 生成一次 Retrieval 或 Hybrid 清单。
2. 点击“清除本工作区检索索引”。
3. 再次生成相同清单。

预期：应用提示清除了多少个内存索引；旧清单立即失效；再次使用时从当前仍获授权的来源重建，结果仍确定一致。

### S24-M07 撤销授权后旧清单不可发送

1. 为一项测试资料生成清单但暂不发送。
2. 从资料面板撤销该来源授权，再尝试继续原发送流程。

预期：旧 Manifest 已失效或 Rust 明确拒绝“资料授权已撤销”；原文件不删除，Provider 不收到该资料。

### S24-M08 外部修改后旧清单不可发送

1. 为 `long.md` 生成清单但暂不发送。
2. 在外部编辑器修改并保存 `long.md`，再尝试确认/发送旧清单。

预期：Rust 拒绝“资料内容已变化，请重新确认上下文”；重新生成后 Hash、范围和估算更新。

### S24-M09 工作区隔离与切换清理

1. 在工作区 A 建立 Retrieval 清单。
2. 切换到工作区 B，再回到 A。

预期：B 看不到 A 的来源或范围；A 的旧待发送清单不可继续使用，新的检索只从 A 当前授权来源重建。

### S24-M10 进程退出不保留索引正文

1. 建立 Retrieval 索引后退出应用并重新启动。
2. 打开同一工作区并点击清除索引，或重新生成清单。

预期：退出前索引不会作为持久记录恢复；清除结果为 0 或只包含本次启动后新建的索引。SQLite Schema 仍为 v10，没有新增正文索引表。
