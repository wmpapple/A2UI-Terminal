# S4.5 性能与可访问性人工验收

> 范围：只验收 S4.5；通过前不得开始 S4.6。  
> Web Mock 用于可复现基准和键盘回归；Desktop 用于真实 WebView2、迁移/恢复和本地成果复验，两者不能相互替代。

## 准备

1. 提交或备份重要工作，并关闭不需要的浏览器和编译进程。
2. 在项目根目录执行一次自动基准：

```powershell
npm run test:e2e -- e2e/performance-accessibility.spec.ts --workers=1 --retries=2
```

3. 确认输出含 `S4.5 performance measurements`，三项 `withinBudget` 都是 `true`。
4. 执行 `npm run desktop:dev`。若本机再次出现随机 Rust 编译崩溃，可在新的 PowerShell 会话使用项目此前已验证的临时单核设置。
5. 准备一个内容较短、已保存的 Markdown 或纯文本成果。不要用大型 PDF、DOCX 或远程 Provider 延迟代替“普通文本成果”基准。

## M01 Desktop 性能门槛

1. 完全退出旧桌面进程后重新执行 `npm run desktop:dev`，首页显示恢复摘要或确认无待恢复项后再计为可交互。
2. 在开发版本按 `F12` 打开开发者工具；若快捷键被系统占用，可从 WebView2 开发工具入口打开 Console。
3. 在 Console 输入 `window.__A2UI_PERFORMANCE__`，找到 `homeInteractive`。其目标为不超过 2500 ms。
4. 从“成果”页打开准备好的普通文本成果，等正文或编辑器出现，再次查看同一数组末尾的 `requestFeedback` 与 `resultOpen`。
5. 记录三项 `durationMs`：请求反馈应不超过 300 ms，普通文本成果打开应不超过 1000 ms。

预期：计时包含首页恢复状态读取和真实成果读取，不用空白界面假装完成；数组只含指标元数据，不出现正文、成果标题、文件名、路径、API Key 或 Endpoint。首次编译时间和 Provider 首字不计入这三项产品交互预算。

## M02 跳至正文与页面焦点

1. 回到首页，将焦点放到窗口内容起点，按一次 `Tab`。
2. 应出现“跳到主要内容”，按 `Enter` 后焦点进入主要内容，并有清晰焦点环。
3. 用 `Tab` / `Shift+Tab` 移动到顶部“成果”，按 `Enter`。
4. 页面切换后，焦点应落在“主要内容”；继续按 `Tab` 可进入成果页控件，不会退回地址栏或丢失在已卸载按钮上。
5. 聚焦一个“继续处理”并按 `Enter`，再次确认焦点进入新成果工作区。

预期：跳转、前进、后退顺序稳定；焦点始终可见；不会因鼠标未参与而卡住。

## M03 纯键盘核心闭环

全程不使用鼠标：

1. 从首页聚焦“写一份文档”，按 `Enter` 打开本地成果对话框，再用 `Esc` 或“关闭”返回。
2. 进入“成果”，打开普通文本成果。
3. 选择“编辑”，在编辑器末尾输入一行文字，等待界面以文字显示“保存中/已保存”。
4. 聚焦“导出”并按 `Enter`，确认系统导出流程可打开；取消保存对话框，不要求生成验收文件。
5. 返回成果页和首页。

预期：所有步骤可由 `Tab`、`Shift+Tab`、方向键、空格、`Enter` 和 `Esc` 完成；保存状态和失败提示都有文字，不只靠颜色。

## M04 读屏、缩放与系统视觉模式

1. 开启 Windows 讲述人（通常为 `Win+Ctrl+Enter`），重复 M02；确认能听到“主导航”“主要内容”“成果工作区”“正在打开成果”和保存状态等含义明确的名称。
2. 将 Windows 或 WebView2 文本/页面缩放设为 200%，检查首页、成果列表、成果工具栏和导出对话框；允许滚动，但主要按钮和文字不能互相覆盖。
3. 开启 Windows 对比度主题，使用键盘走一遍 M03 的打开与取消步骤。
4. 开启系统“关闭动画效果”，确认界面仍可操作且不会依赖动画传达完成状态。

预期：焦点环在普通和强制颜色模式下可见；弱化文字仍可读；成功、失败、草稿、保存中等状态均有文字或图标语义，而不是只有红/绿颜色。

## M05 长成果列表按需显示

1. 打开“成果”，确认列表上方始终显示“已显示 当前数量 / 共 总数项”。即使是 0 项或只有 1—40 项，也必须能看到当前总数。
2. 若当前测试库已有至少 41 项成果，确认首批显示 40 项，并在列表末尾出现“显示更多成果”。
3. 使用键盘激活“显示更多成果”，列表上方的显示数量应增加到 80 或总数；原有顺序、标题和状态保持不变。
4. 若本机没有 41 项成果，不要为了验收污染真实工作区；先用当前少量成果确认总数可见，再以 `ResultsPage.test.tsx` 的 85 项自动回归作为分批加载证据。

预期：成果列表始终显示当前数量和总数；长列表不会一次性渲染全部记录；“显示更多”是普通键盘按钮，增加展示不会删除或改写成果。

## M06 回归与隐私

1. 打开一个存在恢复草稿的成果（若有），确认原 S4.4 的“恢复草稿/保留磁盘版本”仍先由用户选择。
2. 打开导出、版本历史和审阅入口，确认新增焦点管理不会自动接受审阅、保存或覆盖文件。
3. 在开发者工具再次查看 `window.__A2UI_PERFORMANCE__`，关闭并重启应用后确认它是新一轮内存记录，而非历史内容数据库。

预期：恢复、审阅、导出安全边界不变；性能记录不持久化、不上传、不含用户内容。

## 验收回复

全部通过后请回复：`S4.5 验收通过`。若失败，请提供 M 编号、操作步骤、界面提示、是否 Desktop、Windows 缩放/对比度设置，以及三项 `durationMs`；不要发送正文、路径、密钥或敏感截图。
