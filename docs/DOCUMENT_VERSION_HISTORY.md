# 真实文件保存与版本历史

## 保存链路

- 编辑后约 250 ms 将崩溃恢复草稿写入 SQLite，约 1 秒无新输入后自动保存真实文件。
- 保存命令必须携带打开文件时的 SHA-256；磁盘内容已被其他程序修改时返回 `FILE_CONFLICT`，不会覆盖外部内容。
- 普通目录文件和通过系统选择器授权的独立文本文件使用同一保存与版本链路。
- 自动保存写磁盘成功后，以事务记录首次磁盘内容和保存后内容；版本记录失败时回滚磁盘，并重新保留待恢复草稿。

## 版本来源

- `initial`：第一次被版本系统记录的磁盘内容。
- `autosave`：普通编辑或“立即保存”产生的版本。
- `patch`：AI Patch 应用前后的版本，继续关联 Patch 操作与审阅记录。
- `restore`：用户恢复历史版本后产生的新版本。
- `legacy`：数据库升级前无法进一步识别来源的旧记录。

## 查看与恢复

桌面编辑器工具栏提供“版本历史”。列表只读取版本元数据；用户点击预览时才读取该版本正文。恢复时：

1. 若当前编辑器仍有未保存内容，先执行安全保存；保存失败则停止恢复。
2. 后端重新读取磁盘并核对当前 Hash，发生外部冲突时拒绝写入。
3. 当前磁盘内容先进入历史，再把所选版本写回真实文件。
4. 恢复行为创建新的 `restore` 版本，不删除或改写原历史链。

版本默认保留 30 天。每个文件的普通保存/恢复历史最多保留最近 100 条；Patch 审计版本不受该数量上限影响，仍按 30 天规则清理。

## 数据库与兼容

SQLite schema v7 为 `document_versions` 增加 `source` 和 `summary`，并将已有 Patch 版本迁移为 `patch` 来源。升级测试从真实 v6 schema 构造数据库，验证迁移后正文、来源和摘要均保留。
