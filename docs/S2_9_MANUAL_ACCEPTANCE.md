# S2.9 Context Pack 与授权撤销人工验收

> 范围：只验收 S2.9；通过前不得开始 S3.1。

> Web Mock 可以检查交互流程，但不会验证真实文件是否仍在磁盘。持久化、原文件保留和桌面 IPC 必须在 Windows 桌面应用中完成。

## 准备

1. 在项目根目录执行 `npm run desktop:dev`。
2. 从首页“选择资料”导入并确认至少两项非敏感资料，建议一项 Markdown/纯文本和一项 CSV/XLSX。
3. 记住原文件所在位置和文件内容；验收期间不要使用唯一副本或重要文件。

本机若再次遇到随机 Rust 编译崩溃，可在新的 PowerShell 会话中使用已验证的临时设置：

```powershell
(Get-Process -Id $PID).ProcessorAffinity = 1
$env:RUSTUP_TOOLCHAIN = 'stable'
$env:RUST_MIN_STACK = '33554432'
$env:CARGO_INCREMENTAL = '0'
$env:CARGO_BUILD_JOBS = '1'
npm run desktop:dev
```

关闭该 PowerShell 后，以上临时设置结束，不会修改全局工具链。

## M01 “仅本次”资料

1. 进入工作台，发送一条新请求。
2. 在“仅本次使用的已授权资料”中勾选一项资料，点击“生成发送清单”。
3. 确认最终发送清单显示具体文件名，而不是本机绝对路径；点击“确认并发送”。
4. 发送完成后点击“修改发送清单”。

预期：刚才的资料不再勾选；不重新勾选时，后续请求不会继续使用该资料。取消勾选属于缩小发送范围，不应让下一次请求卡在旧的确认状态。

## M02 创建并使用工作区资料包

1. 进入“设置”→“上下文授权与资料包”。
2. 输入资料包名称，选择两项已授权资料并点击“创建资料包”。
3. 回到工作台，点击“修改发送清单”，勾选资料包并保存。
4. 输入请求并发送。
5. 在重新打开的可信发送清单中检查资料包展开结果，然后确认发送。
6. 再发送一条普通请求。

预期：设置页显示资料包名称及其引用的文件名；首次实际挂载时必须再次出现发送前确认，最终清单逐项显示两个具体来源，不能只显示资料包名；确认后同一会话记住该资料包，第二条请求不要求重复选择。

## M03 删除资料包不删除资料

1. 回到“设置”→“上下文授权与资料包”，删除 M02 创建的资料包。
2. 在“已授权的本地资料”中查找刚才的两项资料，并尝试本地预览其中一项。
3. 回到工作台检查发送清单。

预期：资料包消失，但两项资料的授权和原始文件都保留，本地预览仍可用；会话中已保存的资料包选择被移除，不能继续引用已经删除的资料包。

## M04 撤销资料授权与索引同步清理

1. 新建一个只包含一项资料的资料包。
2. 在“已授权的本地资料”中对这项资料点击“移除”，阅读提示后确认“取消授权”。
3. 检查资料列表、资料包列表和工作台发送清单。
4. 再发送一条与该资料相关的请求。
5. 用系统文件管理器打开原文件所在位置。

预期：资料授权立即消失；只含该来源的空资料包自动移除，多来源资料包只移除对应引用；后续发送清单、检索和请求均不再包含该来源；原文件仍在磁盘且内容不变。撤销会使尚未使用的旧 Context Manifest 失效，不能通过旧确认绕过。

## M05 持久化与工作区隔离

1. 新建一个资料包，退出并重新启动桌面应用，恢复同一工作区。
2. 打开设置和工作台，检查资料包及选择状态。
3. 打开或创建另一个工作区，再进入设置。

预期：资料包定义在重启后仍存在；资料包只属于创建它的工作区，另一个工作区不能看到、删除或挂载它；界面和错误提示均不泄露资料绝对路径或正文。

## P0 明确限制

- 资料包只保存已授权来源引用，不复制正文、不复制原文件，也不是永久批准发送。
- 单个资料包最多 20 项，每个工作区最多 50 个资料包；单次最多挂载 10 个资料包。
- 删除资料包与撤销资料授权是两个不同操作：删除资料包保留授权，撤销授权会同步删除对应引用和内存检索索引。
- Web Mock 仅验证界面状态机；SQLite 持久化、Rust 重新鉴权、内存索引清理和原文件保留以桌面应用与自动测试为准。
